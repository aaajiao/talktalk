# Qwen 克隆音色一致性：社区方案核查

日期：2026-11-05。对应 TalkTalk 1.0.8（9）、Qwen3-TTS 1.7B Base 8bit、MLX 流式 ICL。本文是排查依据，不表示问题已经解决。

用户报告不同句子像换了说话人，包含其他男声、女声。1.0.7 的档案身份校验没有消除这一听感；发布 1.0.8 前的小样本 A/B 中，用户选择重复惩罚 1.05 比 1.5 更像本人。后者是当前已知改善，不是连续会议音色稳定性的验收。

## 结论与优先级

本轮检查 Qwen 官方仓库、mlx-audio 的 issue/实际补丁、第三方应用及社区作者的实测。没有找到可直接移植、已证明能在我们的实时 MLX 路径根治逐句换人的方案。

最值得优先核对的是参考录音与参考文字的准确对应。其次才是同一人的不同参考片段、目标语言参考或生成/解码的有界对照。暂不增加逐句整段重生成、声纹门槛、新训练流程或量化档位设置。

### 如何判断“像本人”

2026-10-16 的研究 [Beyond the Benchmark](https://arxiv.org/html/2610.23678v1) 比较 ICL 与 X-Vector，发现准确转写对 ICL 尤其重要，自动指标排序与听者并不完全一致。研究采用 BF16、英语语料，小规模听测，不能直接外推我们中→英/德 8bit 路径的故障率。

因此已有 clone 路由日志、声纹余弦或 F0 只能作辅助证据。应分别记录听感身份、内容是否正确、首声等待和断句；用户听到换人时，不能用高余弦分数否定。X-Vector 也不是已验证优于 ICL 的替换方案。

## 下一步最小排查

1. 核对既有参考录音与实际文本是否完整匹配、句尾是否自然。确认问题后才修改参考，不先让用户重录，不自动用未经核实的 ASR 文本替代。
2. 若参考无误而 1.0.8 仍换声，用少量固定英/德句做有界对照，一次只换一个因素。可优先分离同一生成 codec 的流式/整段解码，判断变化来自生成还是解码；需要相关诊断支持时再做最小实现。
3. 只有前两步不足时，比较本人不同参考片段/同语言参考。微调、更换模型和逐句自动重试暂不纳入。

用户随后提出重新录入、更长内容。重录可作为候选对照，保留旧档案，听验后再决定替换。当前 5–12 秒是产品的有效时长检查，不是 Qwen 的模型限制；过长时提示读快，也可能让录音偏离自然会议语速。若调整录入体验，可考虑约 10–20 秒自然完整语音的候选范围，但它只是待比较的产品建议，不是官方最佳时长，本轮未修改限制。不能由“短参考配错文字更易退化”推导“录得越长音色越稳定”。

本轮只读研究并更新文档，未新增录音、上传声音、运行模型或改动推理代码。音频与个人指标继续留在仓库外；没有压力测试，也不据此发布新版本。

后续用户明确选择 10–20 秒并要求调整稿件、出正式版供重录。1.0.9 据此采用 `zh-v2` 的 71 字新稿和 10–20 秒有效时长范围，原始录音上限 25 秒。旧档案继续可用；重录试听失败保留旧档案。此为上述研究后的产品改动，仍待用户确认新录音的实际音色。

## 重录后的反馈与长句方向

用户随后表示新录音效果更差，并明确要求把重复惩罚从 1.05 恢复 1.5，1.0.10 据此回退该参数。此前“保留旧档案”只覆盖新档案保存前；现有提交实现保存成功后删除旧档案，没有历史恢复槽。查找未找到旧参考/conditioning 副本，故不能宣称已恢复旧声音。新档案现已独立备份，A/B 合成音频不当作原参考使用。

用户观察短句发言较好、长句更容易换声。进一步检查：录音切片约 4.5 秒，但翻译结果不受这个秒数限制，单次 TTS 对整段目标文本连续生成到 EOS；积压摘要另可合并原文，但最近三场未触发它。最近 64 token 的重复惩罚窗口真实生效，decoder 的 72 帧窗口也不意味着主生成器在该时刻忘记参考；暂停调度后继续原生成器，已释放音频后不换种子重试。现有保护能处理跑飞/回声，不能识别“内容正确但声线偏离”。这些区分支持补齐无正文长度诊断，尚不足以证明需要更短切句。

新增社区证据也存在相反结果：[oMLX #516](https://github.com/jundot/omlx/issues/516) 的 CustomVoice 用户报告独立短请求更容易逐段变化；它不是我们 Base 克隆路径的对照。[Voicebox #964](https://github.com/jamiepine/voicebox/pull/964) 用缩块缓解长中文静音后噪声，针对旧版 MLX、离线长文，不能把其字符数或整句重试直接搬入会议。[Qwen #80](https://github.com/QwenLM/Qwen3-TTS/issues/80) 还有德语直接引语/开头引号相关观察，未经确认。因此暂不全局去标点、不固定套用 200 字切块，也不假设长发言必然等于一次长 TTS。

后续带长度元数据的自然发言支持进一步缩小方向：一轮连续发言在约 26.5 秒提交跨度内包含 5 次独立 TTS，每次只有 5–10 词、1.76–2.80 秒，均为停顿切分，没有合并。用户具体描述为“下一句像换了一个人”，应重点比较句间独立生成的一致性，而非假定单次生成太长。按住改点按的提交没有修改合成模型或分段器；它改变了发言控制方式，是否因更频繁的自动句界触发音色变化仍需对照，不能仅凭时间先后断言。

## 同参考分段对照与 1.0.12 决策

在应用关闭时复制当前声音档案作为固定参考，使用原模型、重复惩罚 1.5、相同流式 chunk/参考预热/保护策略。每种语言的一条完整句精确拆成两个子串，不增删词或标点；A 两片分别使用原先按当前文字计算的种子，B 完整句使用其原种子，C 两片都使用 B 的种子。因此 A/C 只改变 seed，B/C 保持同种子但改变分段。分段样本之间插入既有 120 ms 间隔，不逐片归一化音量。

英文和德文各 5 次生成，最后各复现一次 A 的第二片，共 12 次。全部首次通过保护，没有异常重试。重复输入的两对 PCM 均逐字节相同；这排除了本次隔离实验中的跨请求状态残留，但不覆盖真实会话的所有并发条件。辅助相似度仅留作参考，不代替本人听感。

用户试听三组后明确选择 C 更稳定、更像本人。采用同声音/同语言固定初始种子，优先解决正常逐句生成时的采样差异，不增加等待完整句的延迟，也不取消独立请求的 decoder reset。实现保留原 FNV voice 前缀，以此次英/德完整句原始字节为冻结的哈希盐，精确保留 C 的种子；这些文本没有模型提示含义，不传入 TTS。正常发言、告知语和试听共用入口，旧逐文本函数只供显式低层对照。

重试仍保留：未播放前检测到异常才换 successor seed，已播放后不换种子重试。完成诊断补记 attempts/echo_aborts，便于区分今后是正常请求还是重试后的变化。该对照支持当前档案下的修复选择，不证明所有声音/句型或更换参考后都同样稳定。

1.0.12 的后续自然使用提供了反例：约 52 秒连续发言的 15 段全部首次生成、clone 路由、完整播放，用户仍听到句间换声。不能把 C 的少量样本偏好视为问题已解决，也不能再归因于异常重试。应获取经用户授权的真实失败译音，分离生成结果与播放处理的影响；现有无正文日志不能完成这个判断。

## 真实失败录音与参考方式对照

用户随后明确授权一次仅本机的麦克风与生成译音诊断，不录对方、不上传，沿用 24 小时诊断留存。该场已结束：12 段均首次生成和完成播放，无 echo abort；记录的 24 kHz 原始译音共 28.4 秒，各段请求没有交叠，按完成元数据切分的样本总数与原文件一致。记录点在播放处理前，未经过变速、音量、限幅或输出重采样。用户试听此原始译音后明确确认其中已有换声，因此这些播放处理不是本次换声的起点。

退出应用后，仅用现有本地 ASR 核对参考录音及这 12 段译音。参考的 71 个字在去标点后与固定朗读稿一致，没有发现足以支持再次重录或修改参考文字的差异；ASR 一致仍不等于逐字人工验真。原建档 CER 约 1.41%，体现识别检查本身也可能有差异，不能直接推定参考漏字。当前 ICL 验收允许少量文字差异但使用固定稿，作为已知边界保留，不在缺乏证据时扩大改动。

取本场两段译音的本地转写，做 6 次首轮生成：A 当前 ICL 与参考 codec 解码预热；B 只在 talker 输入保留缓存声音向量、仍预热 decoder；C 同 B 但取消预热。均复用现有档案、模型、同一固定数值种子、1.5 重复惩罚、0.16 秒 chunk 和已有保护，不重录、不更改生产配置；实验每句只允许一次尝试，6 次均正常结束，无 runaway/short/echo。B 是混合对照，不能称作纯 x-vector-only；C 与上游 non-ICL 的输入/预热结构一致，但沿用本项目采样策略，不代表上游默认参数。

转写标点不保证等于原始 TTS 输入，第二句不能视作严格复现。第一句 A 的 PCM16 与对应实录切片逐字节一致，已在应用退出后的独立进程复现该段输出；B/C 两句的 CB0 相同，PCM 不同，符合只改变解码预热的控制变量。用户判断三组都不理想，故不采用 x-vector 或取消预热。录音、转写、复现脚本及衍生音频均只保存在同一自动清理诊断目录，未复制到永久 archive 或仓库。生产版本仍为 1.0.12，未据此宣称修复。

进一步从原参考按完整句界截取开头 5.44 秒和结尾 9.18 秒（各含 0.5 秒尾静音），本地 ASR 核对配套文字，分别重算完整声音特征后生成相同的两句话，共 4 次、全部首次完成。保持原固定数值 seed，避免参考 key 改变连带改变采样；只作离线对照。开头参考第二句有 slow 标记，没有异常重试或截断。用户先认为开头明显更好，随后明确纠正：开头参考的第一句较像、间隔后的第二句仍不像；结尾参考后半段明显女声。因此两种短参考均未通过，不能记为短参考修复成功，也未替换现存声音。

同时从保存 WAV 按生产的 `/32767` PCM 转换重建完整 conditioning，ref_codes、ref_text_ids 和 speaker_embed 与已存 blob 逐项完全一致，未发现缓存错档案。24 kHz 路径、权重完整性、参考/目标预填充格式与固定上游一致，静态审计未发现新错位。当前观察仍需区分每次独立生成的变化和单次生成内部的变化；下一步仅把上述两句合为一次生成、保持开头参考和同 seed 做针对性确认，不据此扩大参考长度或采样参数改动。

## 句间上下文对照与 1.0.13
