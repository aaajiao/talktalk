# 字幕与界面改版规格

日期：2026-11-06。起点为 1.0.15（构建 28，main `6fae42c`）。用户在评审后要求“完全按照设计实现所有”，因此下文第 1 节列出的 ARCHITECTURE 条款按建议修改。评审页面：<https://claude.ai/artifact/BA1ZmRALKL9gw1CoGxXAk5>（私有）。本文是实现依据；实现完成后，行为以 [ARCHITECTURE.md](../ARCHITECTURE.md) 为准。

编号沿用评审报告：C 会议/电话格局，V 视频，T 标题栏状态，F 设置流程，VIS 视觉体系。

## 1. 已确认的设计变更

| 原条款 | 新规则 |
|---|---|
| §53/§55/§57 等高四格、四个视口各自滚动、按格冻结 | 会议与电话改为**一条句对时间线**加底部**麦克风状态带**。整条时间线共享一个滚动位置，一起跟随、一起冻结。 |
| §51 阅读文字随宽度等比例缩放 | 会议/电话按 √(宽/760) 缩放并设上下限；视频只由基础字号决定，宽度仅在 640–1200pt 间 ±15% 微调。窗口高度用来增加可见行数。 |
| §61 曲线画在“我·原文”视口背景，固定强调色 | 曲线画在状态带内固定的 24pt 带里，颜色随发声模式：原声绿、译音蓝、播放译音时 1pt 虚线。仍只表示本机采集，不表示远端送达。 |
| §47 视频短暂停顿不自行清空 | 保留不清空；补充“长静默变暗”：最后一页读完后 8 秒无待显句也无原文更新，文字降到 35%、底板降到 40%；新内容到达立即恢复。设置可关闭，默认开。 |
| §57 三种模式共用常驻标题栏 | 三个场景统一悬停显示实底控制条，离开 350ms 后淡出；视频仍保留问题警示符号（黄三角/红八角）。现行规则见 §9.4。 |

不变的约束：浮窗不成为 key window、不抢焦点、排除屏幕共享；三个场景各自记住尺寸、位置、基础字号、不透明度；字幕正文保留 `NSVisualEffectView` 玻璃材质与“降低透明度”优先，控制条独立使用实底；视频不显示波形、不开麦克风；“本机就绪 ≠ Phone 已接收 ≠ 对方听到”；不在字幕正文附加数字核对标注；号码不保存、不写日志；红色关闭只隐藏、黄色最小化不停止工作。

**间距与尺寸**：标题栏 32（视频悬停条 28）；控件高 20、间距 6；“结束”前 8 + 1pt 分隔线 + 8；面板内边距左右 12、底 8；列头 20；说话人轨 24；原文列 40%、列间距 16、译文列 60%；句对上 6 下 8；状态带空闲 48；波形带 24；“回到最新”胶囊高 24。圆角：浮窗 12、设置卡片 10、胶囊 10、芯片 9、视频玻璃块 10、实底行块 6、键帽 5。

**动效**（“减少动态效果”时全部直接切换）：状态带伸缩 180ms easeInOut；草稿→定稿颜色 150ms；视频翻页交叉淡化 120ms；三个场景控制条淡入 200ms、离开 350ms 后用 200ms 淡出；芯片淡入 150ms；通知芯片 4 秒后 300ms 淡出；长静默变暗 300ms；占位提示淡出 120ms。波形不自行动画。

**图标（三处入口统一）**：会议 `person.2.wave.2`，电话 `phone`，视频 `play.rectangle`。原声 `mic.fill`；原声风险 `mic.badge.exclamationmark`（无该符号时叠加 `exclamationmark.circle.fill`）；原声已关/不可用 `mic.slash`（只用于这两态）；翻译收音 `waveform`；播放译音 `speaker.wave.2.fill`；已送入 Phone `phone.arrow.up.right`（只用于这一送达事实）；打开 Phone `arrow.up.forward.app`；未发送／未接入 Phone／本机就绪 `speaker.slash`；声音只在本机（本机试说、仅本机、本机播放、“Phone 未接收”芯片与“仅本机 · Phone 未接收”标签）`laptopcomputer`；重新连接 Phone／音频系统重启 `arrow.triangle.2.circlepath`；已中止 `xmark.octagon`；结束 `stop.circle`（只用于用户自己的结束操作）；键帽动作“开始翻译”用 `translate`，“完成发言”使用文字，不再用 `stop.fill`；视频 `⋯` 菜单 `ellipsis.circle`；收听中 `ear`；锁定 `lock.fill`。问题芯片：云端不可用／key 异常 `network.slash`（`network` 只表示云端翻译已开启与模型更换），这段未发送与文字不支持 `exclamationmark.bubble`（与我的行“未发送”标签一致），未听到对方 `waveform.slash`，会议似乎已结束 `person.2.slash`，录音权限未确认 `hand.raised`。

**标题栏控件颜色（括号内为增强对比度）**：controlStroke 白 35%（70%，“原声已关”描边）；controlDashed 白 50%（80%，“未发送”虚线）；controlFill 白 12%（22%，中性胶囊）；keycapStroke 白 30%（70%）；controlSecondary 白 70%（90%，结束、`⋯`、键帽动作）；controlTertiary 白 60%（90%，chevron、“ · 来源”、场景图标、信息芯片文字）；divider 白 20%（50%，结束前分隔线、信息芯片描边）；noticeStroke 白 28%（60%）。图标字重与旁边文字一致（芯片图标 medium）；仅图标的控件（结束、云端、`⋯`、仅图标芯片）统一 13pt medium。

## 3. 共享标题栏与发声状态（T1–T10、C6）

右侧固定顺序，隐藏的控件不占位：`[发声胶囊 ⌄] [问题/通知芯片] [右⌥ 键帽 + 动作] [Phone ↗] │ [stop.circle]`。整个控制条按 §9.4 悬停显隐，原有字号、配色、胶囊、键帽与图标风格保持不变。

**状态模型拆分**：HUDModel 输出两个独立属性 `voiceState`（发声胶囊，直接读当前发声模式，不参与问题优先级竞选）与 `issueSlot`（问题 > 通知 > 云端说明）。只有 `remoteHearsYourVoice`、`meetingNotUsingMic`、`unavailable` 可以改写胶囊本身；其余问题只进芯片，胶囊保持原色。两者并列显示，互不覆盖。

**发声胶囊**（会议、电话；视频只显示只读的 12pt `ear` 状态图标，不画胶囊，tooltip 与 VoiceOver 仍为“收听中”）：高 20、圆角 10、内边距 8/3、11pt semibold、最小宽 64 最大 180、前置 10pt 图标、右侧 8pt `chevron.down`（60%）。胶囊本身是详情浮层入口，悬停背景加亮 8%。

| 状态 | 文字 | 样式 |
|---|---|---|
| 原声（会议；电话需 Phone 读者已确认） | 原声 | voice.original 实底，深字 |
| 翻译收音 / 处理 / 播放译音 | 译音 | voice.translate 实底，白字 |
| switching（按下未松开） | 松开确认 | voice.translate 描边 |
| restoring | 原声已关 | 白 35% 描边 |
| 本机就绪 / 未发送 | 未发送；电话：未接入 Phone、本机试说 | 白 50% 虚线描边 |
| 电话：Feed 在播但 Phone 读者未确认 | 仅本机 | warn 描边 + 芯片“Phone 未接收” |
| 电话：读者中途断开（清理屏障期间） | 正在重新连接 Phone… | 白 35% 描边 |
| 对方能听到原声 | 对方能听到原声 | risk 实底白字，不缩成泛化“风险”；随控制条显隐，问题事实不会被清除 |
| 音频不可用 | 音频不可用 | warn 实底，黑 85% 字 |

**问题/通知芯片**：高 20、圆角 9、11pt medium、图标加 ≤10 个汉字、最大宽 180、150ms 淡入。问题为 warn/risk 描边，控制条显示时保留到事实消失；收起控制条不清除问题。通知为白 28% 描边、≤8 字、4 秒后淡出（如“✓ 已恢复 TalkTalk Mic”）。`meetingSilent` 显示灰色“未听到对方”（会议时间线为空时由占位表达，芯片让位；视频为“暂无声音”，§9.2.3）。云端隐私说明常驻 16pt `network` 图标加 6pt 蓝点，直到在浮层选“本场不再提示”或“只用 Apple”；会话开始时浮层以 transient 方式自动弹出一次，不抢焦点。所有芯片文字 ≤10 个汉字，完整句子进 detail；`show()` 不再按长度分流；`scripts/check-strings.sh` 增加标题栏短标签的长度检查。

**键帽 + 动作**（会议、电话）：键帽 20 高、最小宽 30、圆角 5、11pt SF Mono、1pt 白 30% 边框；“开始翻译”沿用键帽后的 11pt medium `translate` 图标（白 70%）。结束本次收音改为“完成发言”文字，不再显示 `stop.fill`；VoiceOver 与 tooltip 分别为“右⌥ 开始翻译”“右⌥ 完成发言”，并说明译音播完后恢复原声，同传仍继续。胶囊已写同样文字时键帽不重复（`TitlebarKey.drawsAction`，§9.2.3）：switching 只画按下态键帽，电话本机试说画开始图标；“未接入 Phone”时“本机试说”保留 11pt 文字；窗口宽 < 560 时只显示键帽。translating 时键帽 voice.translate 实底白字；switching 显示按下态。整组不可拖动窗口（cursor 为 arrow），点击打开详情浮层的按键说明。

**Phone ↗**（仅电话）：accessoryBar 风格按钮，`arrow.up.forward.app` + “Phone”，约 64 宽；AX 标签“打开 Phone”，只留图标时 tooltip 为“打开 Phone：在 Phone 中拨号、接听或挂断电话。”。状态里不再出现 phone 图标；`phone.arrow.up.right` 只表示“已送入 Phone”。

**结束**：三个场景一律使用现有 `stop.circle` 图标按钮，默认白 70%，悬停 #FF453A；完整名称“结束会议同传／结束电话同传／结束视频字幕”放在 tooltip 与 AX 中。所有场景点击即结束，不再确认（§9.2.2）；help 说明不会退出会议或挂断电话，以及 TalkTalk 会停止收听、译音，并在接管系统输入时还原系统麦克风；不承诺远端随后听到什么。

**窄窗退让顺序**：来源名截断 → 键帽动作文字 → Phone 只留图标 → 芯片只留图标 → 胶囊缩短为仍能辨认的状态（如原声 / 译音 / 本机 / 恢复中）；风险态最短为“对方听到原声”。控制条显示时胶囊不因窄窗被隐藏。

**详情浮层**（宽 320，NSPopover 原生 darkAqua 材质）：顶部固定一行 24pt 大胶囊加一句后果（“对方听到的是你的原声”“对方听到的是译音”“现在什么都没有发出去”）；第二行“右⌥ → 开始翻译”；然后问题列表、云端说明与操作、打开设置。使用原生 transient `NSPopover`，点击外部或按 Esc 关闭，不设手动“关闭”按钮；普通 tooltip 随鼠标移开消失。输入电平变化不重建浮层。

**左侧**：原生红黄按钮、统一场景图标（设为非无障碍元素）、标题 13pt semibold“场景”+ 13pt regular 60% 白“ · 来源”。

**VoiceOver**：胶囊 AX 标签一行（“发声：原声，对方可听到”），完整说明进 accessibilityHelp；发声模式切换时 `announcementRequested`（high）播报一次短句，例如“原声已关，翻译中”。

## 4. 会议同传：对话时间线（C1–C10、VIS-9）

自上而下：悬停控制条 32 → 列头 20（“原文 · 英语”“译文 · 中文”，整窗只出现一次，语言跟随实际识别与发言目标）→ 时间线（一个滚动视图）→ 麦克风状态带。窗口外框尺寸永远不因内容或状态变化。

**数据**：新增 `ConversationTimeline`（TalkTalkSession 或 Core，可测试），把 SubtitleBoard 的远端句对与我的按键发言（HUDModel 的原文、译文和送达结果）按到达时间合并成有序行。保留窗口沿用现规则：约 60 秒、最多 24 段、原译文合计约 6,000 字符、按完整句对淘汰、始终保留最新一对；只在内存中，不写日志。远端更新仍每 500ms 合并一次，只重建最后一行；状态和电平更新不重建正文。

**句对行**：说话人轨 24 + 原文 40% + 间距 16 + 译文 60%；行高取两列较大者、顶端对齐；行间 0.5pt sep。轨区左缘 3pt 竖条（圆角 1.5）：对方 speaker.remote，我 voice.translate；同一说话人连续行竖条相连，只在一段的首行顶部放 16pt 标记（对方 `person.wave.2.fill`，电话 `phone.fill`；我 `person.crop.circle.fill`，`mic.fill` 在此界面只表示原声），tooltip 为说话人（我／对方／通话对方）。我的行加 meRow 底色，译文末尾显示送达标签。悬停时整行 pairHover。原文高度超过译文 2 倍时截断到译文高度 +1 行，末尾 …⌄（“…”加 0.8× 原文字号的 `chevron.down.circle`，voice.translate；tooltip 与 AX 为“展开原文”），点击就地展开该行。

**三态**：定稿原文 text.source；正在识别的原文 text.sourceLive，句末 2×(F×0.7)pt 静态竖条光标（speaker.remote，不闪烁）；译文草稿与定稿同字号、同字重，颜色 text.draft、末尾“…”、列左缘 2pt voice.translate 50% 竖条，定稿时竖条消失、颜色 150ms 过渡到 text.primary，不回流。Apple 备用翻译不再用“≈”前缀，改为句末 10pt“备用翻译”胶囊（白 12% 底、白 70% 字），tooltip 与 AX 写“云端不可用，本句由 Apple 翻译”。同步修改引导页中关于“≈”的说明。

**送达标签**（我的行，高 18、11pt medium）：会议“已送出”只画 `checkmark.circle.fill`（voice.original、无底，文字在 tooltip 与 AX，§9.2.3）；“未发送”（warn 15% 底、warn 字、`exclamationmark.bubble`，字号与原文相同，替代原来 12pt 另起一行的“未发送草稿”）。电话见第 5 节。

**冻结与回到最新**：手动上翻后整条时间线冻结，只额外保留一份最新显示快照；时间线底部、状态带上方 8pt 居中浮出胶囊（高 24、圆角 12、hudWindow、1pt 白 18% 描边、12pt medium）“[`arrow.down`] N 条新字幕”（11pt semibold 箭头，tooltip“回到最新字幕”，AX“N 条新字幕，回到最新”），N 为冻结快照后新增的定稿数。点击或滚回底部恢复跟随。新一轮自己的翻译发言或会话重置立即解除冻结并替换快照。标题行不再放按钮。

**麦克风状态带**（空闲 48pt，上缘 0.5pt 分隔）：左起状态图标 16pt + 状态文字 13pt semibold（发声状态色）+ 12pt 后果说明（白 60%）；中间弹性波形区高 24、线宽 1.5、振幅上限 10、颜色为发声状态色 55%，沿用现有 RMS 映射，RMS < −50dB 收平，250ms 无有效输入时移除；右侧只在风险／不可用时放修复／详情，不再重复标题栏键帽（§9.2.3）。

| 状态 | 状态带文字 | 波形 |
|---|---|---|
| original | 原声 · 对方能听到你 | 绿 |
| translating | 翻译中 · 原声已关 | 蓝 |
| switching | 松开 右⌥ 确认 | 蓝描边态 |
| draining | 译音播放中 · 原声已关 | 1pt 蓝虚线 |
| restoringOriginal | 正在恢复原声… | 收平 |
| ready / 未发送 | 未发送 · 对方听不到你 | 收平 |
| remoteHearsYourVoice / meetingNotUsingMic | 对方能听到原声 · 会议没有使用 TalkTalk Mic | 无；risk 18% 底 + 左 3pt 红条 + “修复…”按钮 |
| unavailable | 音频不可用 · 未发送 | 无；warn 15% 底 |

状态行、波形、状态操作和该行分隔线随悬停控制条显隐；固定占位保留，不重排时间线，不隐藏下面的本人实时原文和译文。

**发言态**：从翻译锁存开始，到 speechWorkPending 结束后再过 3 秒，状态带在 180ms 内展开到 min(内容高 34%, 160pt)：上排状态行与波形，下面是我的实时中文原文（0.78F，sourceLive）与译文草稿（0.86F，draft，末尾“…”），底色 rgba(64,156,255,0.10)、左缘 3pt voice.translate。定稿后这一组作为“我的行”插入时间线，状态带收回 48pt。

**断点**：内容宽 < 520 时句对改为上下堆叠（译文在上、原文在下 0.78F），列头隐藏；内容高 < 260 时状态带收成 28pt 单行（图标、短标签、迷你波形）；内容高 < 140 时只保留时间线最后一行与 28pt 状态带。关闭全部正文时仍只保留标题栏，不覆盖已保存的阅读尺寸。

**空状态**：时间线居中 13pt 白 45%“[`ear`] 正在听 Zoom…”（来源取实际名称）；`meetingSilent` 时改为“[`waveform.slash`] 暂未听到对方声音”（tooltip“查看详情”），点击打开详情。图标与文字同色、同 13pt，间隔 4pt。状态带显示当前发声状态；“点按右⌥翻译你的发言”只在第一次自己的发言之前显示（§9.2.3）。第一条字幕到达后占位 120ms 淡出。

**无障碍**：每个句对行一个 AX 元素，标签“对方：译文……；原文……”或“我：……”；新增“朗读新译文（VoiceOver）”开关，默认关，开启且窗口可见时每条译文定稿 post `announcementRequested`（medium），草稿不播报。

## 6. 视频字幕（V1–V11）

**窗口**：透明窗口使用 `.fullSizeContentView`；默认内容 960×184，为原 150pt 阅读空间增加 28pt 控制条与 6pt 间距，最小高也预留这 34pt。悬停（追踪区 `.activeAlways`）时 28pt 实底控制条在 200ms 内淡入：红黄按钮、[`play.rectangle`] 来源名（12pt semibold；“视频字幕 · 来源”在 tooltip、VoiceOver 与窗口标题中）、`ear` 收听图标、`⋯` 菜单（含“锁定字幕位置”）和 `stop.circle` 结束图标；离开 350ms 后用 200ms 淡出；VoiceOver 运行或正文关闭时常显。控制条与稳定阅读区同宽、水平居中，位于字幕外接框上方 6pt；显隐不改变字幕基线。黄/红问题时右上角常显 10pt 警示符号（白色叹号，黄 `exclamationmark.triangle.fill`／红 `exclamationmark.octagon.fill`，带阅读阴影），点击打开详情浮层。默认位置为距屏幕底边 8% `visibleFrame` 高度，水平居中。

**排版**：原文在上、中文在下（设置可选“中文在上”）。中文文本块最大宽 20×中文字号，每页最多 2 行；原文最大宽 46 个字符（约 46×0.52×字号），每页最多 2 行；两块间距 6pt，水平居中，**整体底部锚定**：中文末行基线距内容底边 12pt，单行时整体下沉。窗口加宽只增加两侧留白。窄窗（< 640）时文本块宽 = 窗口宽 − 48，中文下限 18pt、原文下限 14pt。

**分页**：一页中文约 40 字；断点优先在“，。；？！、”及 `, ; . ?` 之后，向前回找不超过半行；两行均衡换行，第二行不得只剩 1–2 字或单个标点。阅读时长规则不变（原文约 18 字符/秒、中文约 9 字/秒，取较长者，1–6 秒；重复停留一侧不再计时；翻完当前句才切下一句；隐藏/最小化暂停）。有待显句时当前句每页时长 ×0.7（下限 1 秒），先追赶，追不上才淘汰较旧待显句。

**视觉反馈**：翻页 120ms 交叉淡化（两页间留 1 帧空白）；句子还有下一页时中文块下 4pt 画页点（§9.2.3 起不再另加“›”）（3pt 圆点，间距 4，当前页白 90%、其余 30%；增强对比度 100%／50%），最后一页不显示，数据用 VideoSubtitleView 现有 `pageCount` / `currentPageIndex`。草稿同字号，只有与上一版不同的尾部用白 65% 并在句末加“…”，定稿 150ms 过渡到 100%。丢句时在原文位置显示 1.5 秒“已跳过 1 句”（12pt，白 50%，增强对比度 75%）。字幕落后 > 5 秒时右上角显示黄色警示符号，悬停条显示固定的“字幕落后”（`clock.badge.exclamationmark`，§9.2.3）。长静默变暗见第 1 节。空状态在原文位置显示“[`ear`] 正在听 Google Chrome…”（14pt，白 60%，增强对比度 80%；13pt 图标同色；来源取实际名称）。

**字幕样式**（字幕设置里视频专属，三选一，按场景保存）：

1. 贴合玻璃（默认）：窗口背景透明，`NSVisualEffectView(.hudWindow)` 的宽度与控制条共用稳定阅读宽度（原文／译文目标宽较大者 + 左右各 16pt，限于窗口宽度），不随短句逐字收窄；高度仍包住实际文字及上下各 10pt，圆角 10，alpha 为场景不透明度。控制条始终实底，不受此 alpha 影响；阅读区外保持透明。不透明度 < 0.75 时叠加描边样式的阴影。
2. 描边：无底板；`NSShadow` 黑 85%、模糊 3.5、偏移 (0,−1)，加 `strokeWidth −3` 黑色描边（同时设前景色以保持填充）。不透明度滑块置灰并说明“描边样式不使用背景”。
3. 实底：每行文字后垫圆角 6、rgba(0,0,0,0.62) 的行块，左右 0.4em。系统“降低透明度”开启时自动使用此样式，不透明度 0.85。

**鼠标穿透**：“锁定字幕位置（鼠标穿透）”在会中菜单栏菜单与悬停条 `⋯` 中。锁定后 `ignoresMouseEvents = true`、不响应拖动，只能从菜单栏解锁；锁定时右上角显示 10pt `lock.fill`（40%，增强对比度 80%，带阅读阴影；VoiceOver help 说明从菜单栏解锁）。未锁定时只有文字块与悬停条响应拖动，透明区域显式设置是否接收点击。锁定状态按场景保存。首次出现在全屏 Space 时提示一次“可拖到画面外，或在菜单中锁定”。

**无障碍**：两个文本区 AX 标签“原文 · 英语”“译文 · 中文”；开启朗读时每条中文定稿播报一次。

## 9. 实现记录

2026-11-06 起，按 W1（令牌与标题栏）、W2（三态文字与视频分页）、W3（时间线与状态带）、W4（视频窗口）、W5（字幕设置）、设置流程分支依次实现，并合入 main，构建号升为 29。未启动应用，下列取舍均未经实机验证。与本规格的差异：

- **键帽动作与状态带**：
  - 键帽动作：处理／排空时用“开始翻译”；电话读者未确认时一律为“本机试说”。

- **云端提示锚点**：一次性云端提示锚定网络图标，问题芯片占位时改锚定胶囊。
- **标题栏高度与图标**：按 §9.4 在内容区使用固定 32pt（视频 28pt）控制条，现有控件在条内居中，原生标题栏容器隐藏。当前 SDK 没有 `mic.badge.exclamationmark`，使用 `mic.fill` 叠加 `exclamationmark.circle.fill`。

  - 我的行的实时原文光标用 voice.translate，对方行按规格用 speaker.remote。

  - 贴合玻璃只铺一块，纵向覆盖两个文本块的外接框，横向按 §9.4 使用稳定阅读宽度。
  - 页点限制在内容区内；“中文在上”时，多页句子会让两块间距增加页点高度。

- **视频窗口**：
  - 隐藏绿色缩放按钮；警示符号画在内容中，点击区在标题栏尾部预留的 26pt 内，所以视频的“结束”内移 26pt。

- **时间线**：
  - 列头只描述远端语言。
  - 我的行按本轮首个非空原文排序，60 秒从提交时计；这是内存中的有界阅读窗口，取代旧规则“不建立发言历史”。
  - 字幕重置只清远端句对，会话结束和换场景全部清空。
  - 未得到定稿的非原声轮次以草稿样式保留；“已中止”用 warn 色加 `xmark.octagon`。
  - “↓ N 条新字幕”只在冻结且 N > 0 时出现。

### 9.1 HIG 与图标优先专项（2026-11-06）

用户为本轮定了两条原则：“1. 设计要符合苹果的标准  2. 能用图标表达的就不要写字（图形一定要起到足够的作用）”。按与用户确认的理解执行：

- **P1 Apple HIG（macOS 26）**：优先使用原生控件与材质（NSPopover、分组 Form、分段控件、菜单）。SF Symbols 按场合选尺寸、字重和渲染模式（hierarchical／palette）。规格未定令牌时用系统色。菜单遵循惯例：打开窗口或需进一步输入的项加“…”，开关项用勾选，键盘等价由系统绘制。破坏性操作就地确认。支持键盘、VoiceOver、减少动态效果、增强对比度和减少透明度。
- **P2 图标优先**：SF Symbol 能无歧义表达时，用它替代或缩短文字。状态差异要能从形状、颜色或符号看出，不只靠文字。每个只有图标的控件都保留本地化 tooltip（`.help`／`toolTip`）和 AX 标签（zh-Hans，见 `Resources/Localizable.xcstrings`）。
- **硬例外（安全语义）**：项目规则为“本机就绪 ≠ Phone 读者已确认 ≠ 对方已听到”。凡是误读会让用户对错误对象说话的状态，都保留图标加最短文字，只允许加强旁边的图标。

#### 9.2.2 一步退出，不再确认（2026-11-06，字幕窗口）

用户反馈：“有一些注释和退出都特别繁琐，而且一直有个问题：字幕退出的时候有个中间状态，会先缩到剩一条然后再退出，就不能直接退出来吗？”本节取代 §3“结束”、§9 第 263 行与 §9.1“刻意保留为文字”中关于结束确认的内容。

- **根因**：窗口只在会话到 `.idle/.ended`、即整个异步停止结束后才隐藏；隐藏时先清掉字幕再排版，标题栏状态（如结束时还原输入产生的“系统麦克风已还原”通知，它刻意跨过 `meetingEnded` 保留 4 秒）仍在，于是先缩成仅标题栏的一条，通知消失后才移出。自动、失败与睡眠后的结束更糟：还原通知在窗口已移出后到达，会把窗口重新拉回成一条；空闲时“现在还原默认输入”也会弹出一条。
- **会话闸门**：`SubtitleWindowPresence`（TalkTalkCore，带测试）。只有 `beginSession`（会话 `.started`、引导示例播放、smoke；§9.2.3 起电话不再在准备开始时打开）打开；`endSession` 先关闸并移出窗口（或撤掉 Dock 缩略图），再做隐藏后的清理，可重复调用。状态、通知、`setVisible(true)` 都不能重新打开。会话中关闭字幕时的仅标题栏模式不变。
- **任何原因一步消失**：会话新增仅供界面的 `MeetingEvent.stopping(reason)`，在停止开始时发出一次（不属于生命周期事件）；`MeetingController` 收到后关闸、置 `meetingStopping`（菜单显示“正在结束…”），到 `.idle` 时清除。用户结束在同一轮点击中先关闸，再还原系统输入，通知落在已隐藏的窗口里。开始失败或放弃时也关闸。引导试说的结束与失败、示例停止、⌘Q 都先关闸；退出时“麦克风尚未还原”警告框单独出现。

### 9.4 字幕悬停与提示微调（2026-11-07）

本节是用户确认的现行设计，取代前文与之冲突的常显标题栏、停止图标、提示及关闭方式。沿用现有 SF Symbols、颜色、字号、胶囊、键帽、原译双栏和底部状态带，只调整显隐、对齐及文案；音频与字幕处理流程不因界面变化而改变。

- **三场景统一显隐**：指针进入字幕窗口时显示控制条；离开后等待 350ms，再以 200ms 淡出，淡入同为 200ms。“减少动态效果”时直接切换；VoiceOver 运行时或正文关闭、窗口只剩控制条时保持显示。打开本窗口的菜单或详情浮层时保持已显示的条；关闭浮层不清除持续问题。视频锁定穿透的既有规则仍优先。
- **保留正文与结构**：会议／电话底部仅隐藏纯状态行、波形、状态操作及该行分隔线，保留固定占位与本人实时原译文；上方时间线、手动滚动位置和字幕基线不因悬停显隐移动。原有状态带展开、紧凑断点与自己的发言归入时间线规则保持不变。
- **实底控制条**：三场景控制条使用原生深色外观的实底，透明度不跟随字幕背景滑块。字幕正文继续使用现有玻璃／描边／实底样式，以及减少透明度和增强对比度规则。
- **视频对齐**：稳定阅读宽度为原文／译文目标块宽的较大者加左右各 16pt，限于窗口宽度；贴合玻璃与控制条共用此宽度。控制条位于实际字幕框上方 6pt，顶部预留 34pt（28pt 条 + 6pt 间距），默认逻辑窗口 960×184。正文仍底部锚定，末行基线距底边 12pt；控制条显示与隐藏不改变分页或正文位置。指针正在操作条或浮层时，避免文字更新把控件从指针下移走。
- **两种结束明确分开**：结束整场一律为 `stop.circle` 图标，默认灰、悬停红，tooltip／AX 明确命名所在场景。右⌥结束本次收音改为“完成发言”，不再画 `stop.fill`；窄窗仅保留键帽时，tooltip／AX 仍完整说明。点击键帽只看按键说明，实体右⌥才切换发言；结束整场点击即生效，不增加确认。结束电话同传不会挂断电话，结束会议同传不会退出会议；后果只陈述 TalkTalk 停止工作及系统麦克风还原，不推断远端随后听到什么。
- **原生提示关闭**：普通 tooltip 在悬停时显示，移开后消失。详情与云端说明沿用 transient `NSPopover`，点外部或按 Esc 关闭，不设手动“关闭”按钮，也不新增结束确认浮层。
- **提示按事实分工**：顶部胶囊表示发声模式，底部状态行说明收音／处理／播放阶段，问题芯片补充异常原因。Phone 读者是否存在只说明 Phone 是否接收音频，不代表电话是否接通；未确认时写“Phone 尚未接收音频”，空字幕写“等待对方字幕…”。本机试说按真实阶段写“本机收音中”或“本机译音处理中”；仅本机实际播放写“本机译音播放中”，不在底部再重复芯片原因。进行中的译音用“译音播放中”与“正在送入 Phone”，已完成句子的送达标签保留“已送入 Phone”，不声称对方已听到。
- **设置预览**：继续复用真实组件与固定样例，三个场景均响应悬停，显示同样的实底控制条和底部状态显隐；样例不会启动音频或会话，窗口操作仍不可执行。视频按 960:184 缩放。验证结果单独记录，本节不代表实机验收通过。
