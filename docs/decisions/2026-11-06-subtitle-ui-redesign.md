# 字幕与界面改版规格

日期：2026-11-06。起点为 1.0.15（构建 28，main `6fae42c`）。用户在评审后要求“完全按照设计实现所有”，因此下文第 1 节列出的 ARCHITECTURE 条款按建议修改。评审页面：<https://claude.ai/artifact/BA1ZmRALKL9gw1CoGxXAk5>（私有）。本文是实现依据；实现完成后，行为以 [ARCHITECTURE.md](../ARCHITECTURE.md) 为准。

编号沿用评审报告：C 会议/电话格局，V 视频，T 标题栏状态，F 设置流程，VIS 视觉体系。

## 1. 已确认的设计变更

| 原条款 | 新规则 |
|---|---|
| §53/§55/§57 等高四格、四个视口各自滚动、按格冻结 | 会议与电话改为**一条句对时间线**加底部**麦克风状态带**。整条时间线共享一个滚动位置，一起跟随、一起冻结。 |
| §51 阅读文字随宽度等比例缩放 | 会议/电话按 √(宽/760) 缩放并设上下限；视频只由基础字号决定，宽度仅在 640–1200pt 间 ±15% 微调。窗口高度用来增加可见行数。 |
| §61 曲线画在“我·原文”视口背景，固定强调色 | 曲线画在状态带内固定的 24pt 带里，颜色随发声模式：原声绿、译音蓝、播放译音时 1pt 虚线。仍只表示本机采集，不表示远端送达。 |
| §47 视频短暂停顿不自行清空 | 保留不清空；补充“长静默变暗”：最后一页读完后 8 秒无待显句也无原文更新，文字降到 35%、底板降到 40%；新内容到达立即恢复。设置可关闭，默认开。 |
| §57 三种模式共用常驻标题栏 | 会议/电话保持常驻；**视频**改为悬停才显示标题栏，有问题时右上角常显 10pt 警示符号（黄三角/红八角）。 |

不变的约束：浮窗不成为 key window、不抢焦点、排除屏幕共享；三个场景各自记住尺寸、位置、基础字号、不透明度；保留 `NSVisualEffectView` 玻璃材质与“降低透明度”优先；视频不显示波形、不开麦克风；“本机就绪 ≠ Phone 已接收 ≠ 对方听到”；不在字幕正文附加数字核对标注；号码不保存、不写日志；红色关闭只隐藏、黄色最小化不停止工作。

## 2. 令牌（`SubtitleTokens` / `ConversationTypography` / `VideoCaptionTypography`）

**间距与尺寸**：标题栏 32（视频悬停条 28）；控件高 20、间距 6；“结束”前 8 + 1pt 分隔线 + 8；面板内边距左右 12、底 8；列头 20；说话人轨 24；原文列 40%、列间距 16、译文列 60%；句对上 6 下 8；状态带空闲 48；波形带 24；“回到最新”胶囊高 24。圆角：浮窗 12、设置卡片 10、胶囊 10、芯片 9、视频玻璃块 10、实底行块 6、键帽 5。

**动效**（“减少动态效果”时全部直接切换）：状态带伸缩 180ms easeInOut；草稿→定稿颜色 150ms；视频翻页交叉淡化 120ms；视频标题栏淡入 200ms、离开 1.5 秒后淡出；芯片淡入 150ms；通知芯片 4 秒后 300ms 淡出；长静默变暗 300ms；占位提示淡出 120ms。波形不自行动画。

**图标（三处入口统一）**：会议 `person.2.wave.2`，电话 `phone`，视频 `play.rectangle`。原声 `mic.fill`；原声风险 `mic.badge.exclamationmark`（无该符号时叠加 `exclamationmark.circle.fill`）；原声已关/不可用 `mic.slash`（只用于这两态）；翻译收音 `waveform`；播放译音 `speaker.wave.2.fill`；已送入 Phone `phone.arrow.up.right`（只用于这一送达事实）；打开 Phone `arrow.up.forward.app`；未发送／未接入 Phone／本机就绪 `speaker.slash`；声音只在本机（本机试说、仅本机、本机播放、“Phone 未接收”芯片与“仅本机 · Phone 未接收”标签）`laptopcomputer`；重新连接 Phone／音频系统重启 `arrow.triangle.2.circlepath`；已中止 `xmark.octagon`；结束 `stop.circle`（只用于用户自己的结束操作）；键帽动作 开始翻译 `translate`、结束 `stop.fill`；视频 `⋯` 菜单 `ellipsis.circle`；收听中 `ear`；锁定 `lock.fill`。问题芯片：云端不可用／key 异常 `network.slash`（`network` 只表示云端翻译已开启与模型更换），这段未发送与文字不支持 `exclamationmark.bubble`（与我的行“未发送”标签一致），未听到对方 `waveform.slash`，会议似乎已结束 `person.2.slash`，录音权限未确认 `hand.raised`。

**标题栏控件颜色（括号内为增强对比度）**：controlStroke 白 35%（70%，“原声已关”描边）；controlDashed 白 50%（80%，“未发送”虚线）；controlFill 白 12%（22%，中性胶囊）；keycapStroke 白 30%（70%）；controlSecondary 白 70%（90%，结束、`⋯`、键帽动作）；controlTertiary 白 60%（90%，chevron、“ · 来源”、场景图标、信息芯片文字）；divider 白 20%（50%，结束前分隔线、信息芯片描边）；noticeStroke 白 28%（60%）。图标字重与旁边文字一致（芯片图标 medium）；仅图标的控件（窄窗结束、云端、`⋯`、仅图标芯片）统一 13pt medium。

## 3. 共享标题栏与发声状态（T1–T10、C6）

右侧固定顺序，隐藏的控件不占位：`[发声胶囊 ⌄] [问题/通知芯片] [右⌥ 键帽 + 动作] [Phone ↗] │ [结束]`。

**状态模型拆分**：HUDModel 输出两个独立属性 `voiceState`（发声胶囊，直接读当前发声模式，不参与问题优先级竞选）与 `issueSlot`（问题 > 通知 > 云端说明）。只有 `remoteHearsYourVoice`、`meetingNotUsingMic`、`unavailable` 可以改写胶囊本身；其余问题只进芯片，胶囊保持原色。两者并列显示，互不覆盖。

**发声胶囊**（会议、电话；视频只显示只读的 12pt `ear` 状态图标，不画胶囊，tooltip 与 VoiceOver 仍为“收听中”）：高 20、圆角 10、内边距 8/3、11pt semibold、最小宽 64 最大 180、前置 10pt 图标、右侧 8pt `chevron.down`（60%）。胶囊本身是详情浮层入口，悬停背景加亮 8%。

| 状态 | 文字 | 样式 |
|---|---|---|
| 原声（会议；电话需 Phone 读者已确认） | 原声 | voice.original 实底，深字 |
| 翻译收音 / 处理 / 播放译音 | 译音 | voice.translate 实底，白字 |
| switching（按下未松开） | 松开确认 | voice.translate 描边 |
| restoring | 原声已关 | 白 35% 描边 |
| 本机就绪 / 未发送 | 未发送；电话：未接入 Phone、本机试说 | 白 50% 虚线描边 |
| 电话：Feed 在播但 Phone 读者未确认 | 仅本机 | warn 描边 + 芯片“Phone 未接收” |
| 电话：读者中途断开（清理屏障期间） | 正在重新连接 Phone… | 白 35% 描边 |
| 对方能听到原声 | 对方能听到原声 | risk 实底白字，常显不可收起 |
| 音频不可用 | 音频不可用 | warn 实底，黑 85% 字 |

**问题/通知芯片**：高 20、圆角 9、11pt medium、图标加 ≤10 个汉字、最大宽 180、150ms 淡入。问题为 warn/risk 描边，常显到事实消失。通知为白 28% 描边、≤8 字、4 秒后淡出（如“✓ 已恢复 TalkTalk Mic”）。`meetingSilent` 显示灰色“未听到对方”。云端隐私说明常驻 16pt `network` 图标加 6pt 蓝点，直到在浮层选“本场不再提示”或“只用 Apple”；会话开始时浮层以 transient 方式自动弹出一次，不抢焦点。所有芯片文字 ≤10 个汉字，完整句子进 detail；`show()` 不再按长度分流；`scripts/check-strings.sh` 增加标题栏短标签的长度检查。

**键帽 + 动作**（会议、电话）：键帽 20 高、最小宽 30、圆角 5、11pt SF Mono、1pt 白 30% 边框；“开始翻译”“结束”在任何宽度都以键帽后的 11pt medium 图标显示（`translate`／`stop.fill`，白 70%，翻译中为 voice.translate），VoiceOver 与 tooltip 仍为“右⌥ 开始翻译”“右⌥ 结束”；“松开确认”“本机试说”保留 11pt 文字（`SpeechStatusPresentation.keyAction`），窗口宽 < 560 时只显示键帽。translating 时键帽 voice.translate 实底白字；switching 显示按下态。整组不可拖动窗口（cursor 为 arrow），点击打开详情浮层的按键说明。

**Phone ↗**（仅电话）：accessoryBar 风格按钮，`arrow.up.forward.app` + “Phone”，约 64 宽；AX 标签“打开 Phone”，只留图标时 tooltip 为“打开 Phone：在 Phone 中拨号、接听或挂断电话。”。状态里不再出现 phone 图标；`phone.arrow.up.right` 只表示“已送入 Phone”。

**结束**：11pt 文字按钮，默认白 70%，悬停 #FF453A；会议、电话写“结束同传”，视频“结束”。会议、电话点击后从按钮弹出 260 宽的 `NSPopover` 确认，不要求浮窗成为 key：

- 电话：标题“结束电话同传？”，正文“通话不会挂断；结束后对方将听不到你的声音。”，按钮“取消”“结束同传”（systemRed）。
- 会议：标题“结束会议同传？”，正文按当时状态填写，例如“会议仍会收到你的原声”或“会议将听不到你的声音”。
- 视频：直接结束。

**窄窗退让顺序**：来源名截断 → 键帽动作文字 → Phone 只留图标 → 结束只留 `stop.circle` → 芯片只留图标 → 胶囊缩成两字（原声 / 译音 / 本机）；风险态最短为“对方听到原声”。胶囊永远不隐藏。

**详情浮层**（宽 320，NSPopover 原生 darkAqua 材质）：顶部固定一行 24pt 大胶囊加一句后果（“对方听到的是你的原声”“对方听到的是译音”“现在什么都没有发出去”）；第二行“右⌥ → 开始翻译”；然后问题列表、云端说明与操作、打开设置。关闭按钮、点击外部关闭；输入电平变化不重建浮层。

**左侧**：原生红黄按钮、统一场景图标（设为非无障碍元素）、标题 13pt semibold“场景”+ 13pt regular 60% 白“ · 来源”。

**VoiceOver**：胶囊 AX 标签一行（“发声：原声，对方可听到”），完整说明进 accessibilityHelp；发声模式切换时 `announcementRequested`（high）播报一次短句，例如“原声已关，翻译中”。

## 4. 会议同传：对话时间线（C1–C10、VIS-9）

自上而下：标题栏 32 → 列头 20（“原文 · 英语”“译文 · 中文”，整窗只出现一次，语言跟随实际识别与发言目标）→ 时间线（一个滚动视图）→ 麦克风状态带。窗口外框尺寸永远不因内容或状态变化。

**数据**：新增 `ConversationTimeline`（TalkTalkSession 或 Core，可测试），把 SubtitleBoard 的远端句对与我的按键发言（HUDModel 的原文、译文和送达结果）按到达时间合并成有序行。保留窗口沿用现规则：约 60 秒、最多 24 段、原译文合计约 6,000 字符、按完整句对淘汰、始终保留最新一对；只在内存中，不写日志。远端更新仍每 500ms 合并一次，只重建最后一行；状态和电平更新不重建正文。

**句对行**：说话人轨 24 + 原文 40% + 间距 16 + 译文 60%；行高取两列较大者、顶端对齐；行间 0.5pt sep。轨区左缘 3pt 竖条（圆角 1.5）：对方 speaker.remote，我 voice.translate；同一说话人连续行竖条相连，只在一段的首行顶部放 16pt 标记（对方 `person.wave.2.fill`，电话 `phone.fill`；我 `person.crop.circle.fill`，`mic.fill` 在此界面只表示原声），tooltip 为说话人（我／对方／通话对方）。我的行加 meRow 底色，译文末尾显示送达标签。悬停时整行 pairHover。原文高度超过译文 2 倍时截断到译文高度 +1 行，末尾 …⌄（“…”加 0.8× 原文字号的 `chevron.down.circle`，voice.translate；tooltip 与 AX 为“展开原文”），点击就地展开该行。

**三态**：定稿原文 text.source；正在识别的原文 text.sourceLive，句末 2×(F×0.7)pt 静态竖条光标（speaker.remote，不闪烁）；译文草稿与定稿同字号、同字重，颜色 text.draft、末尾“…”、列左缘 2pt voice.translate 50% 竖条，定稿时竖条消失、颜色 150ms 过渡到 text.primary，不回流。Apple 备用翻译不再用“≈”前缀，改为句末 10pt“备用翻译”胶囊（白 12% 底、白 70% 字），tooltip 与 AX 写“云端不可用，本句由 Apple 翻译”。同步修改引导页中关于“≈”的说明。

**送达标签**（我的行，高 18、11pt medium）：会议“已送出”（voice.original 文字 + `checkmark.circle.fill`、无底）；“未发送”（warn 15% 底、warn 字、`exclamationmark.bubble`，字号与原文相同，替代原来 12pt 另起一行的“未发送草稿”）。电话见第 5 节。

**冻结与回到最新**：手动上翻后整条时间线冻结，只额外保留一份最新显示快照；时间线底部、状态带上方 8pt 居中浮出胶囊（高 24、圆角 12、hudWindow、1pt 白 18% 描边、12pt medium）“[`arrow.down`] N 条新字幕”（11pt semibold 箭头，tooltip“回到最新字幕”，AX“N 条新字幕，回到最新”），N 为冻结快照后新增的定稿数。点击或滚回底部恢复跟随。新一轮自己的翻译发言或会话重置立即解除冻结并替换快照。标题行不再放按钮。

**麦克风状态带**（空闲 48pt，上缘 0.5pt 分隔）：左起状态图标 16pt + 状态文字 13pt semibold（发声状态色）+ 12pt 后果说明（白 60%）；中间弹性波形区高 24、线宽 1.5、振幅上限 10、颜色为发声状态色 55%，沿用现有 RMS 映射，RMS < −50dB 收平，250ms 无有效输入时移除；右侧键帽组件。

| 状态 | 状态带文字 | 波形 |
|---|---|---|
| original | 原声 · 对方能听到你 | 绿 |
| translating | 翻译中 · 原声已关 | 蓝 |
| switching | 松开 右⌥ 确认 | 蓝描边态 |
| draining | 译音播放中 · 原声已关 | 1pt 蓝虚线 |
| restoringOriginal | 正在恢复原声… | 收平 |
| ready / 未发送 | 未发送 · 对方听不到你 | 收平 |
| remoteHearsYourVoice / meetingNotUsingMic | 对方能听到原声 · 会议没有使用 TalkTalk Mic | 无；risk 18% 底 + 左 3pt 红条 + “修复…”按钮 |
| unavailable | 音频不可用 · 未发送 | 无；warn 15% 底 |

**发言态**：从翻译锁存开始，到 speechWorkPending 结束后再过 3 秒，状态带在 180ms 内展开到 min(内容高 34%, 160pt)：上排状态行与波形，下面是我的实时中文原文（0.78F，sourceLive）与译文草稿（0.86F，draft，末尾“…”），底色 rgba(64,156,255,0.10)、左缘 3pt voice.translate。定稿后这一组作为“我的行”插入时间线，状态带收回 48pt。

**断点**：内容宽 < 520 时句对改为上下堆叠（译文在上、原文在下 0.78F），列头隐藏；内容高 < 260 时状态带收成 28pt 单行（图标、短标签、迷你波形）；内容高 < 140 时只保留时间线最后一行与 28pt 状态带。关闭全部正文时仍只保留标题栏，不覆盖已保存的阅读尺寸。

**空状态**：时间线居中 13pt 白 45%“[`ear`] 正在听 Zoom 的会议声音…”（来源取实际名称）；`meetingSilent` 时改为“[`info.circle`] 暂未听到对方声音”（tooltip“查看详情”），点击打开详情。图标与文字同色、同 13pt，间隔 4pt。状态带显示当前发声状态与“点按 右⌥ 开始翻译你的发言”。第一条字幕到达后占位 120ms 淡出。

**无障碍**：每个句对行一个 AX 元素，标签“对方：译文……；原文……”或“我：……”；新增“朗读新译文（VoiceOver）”开关，默认关，开启且窗口可见时每条译文定稿 post `announcementRequested`（medium），草稿不播报。

## 6. 视频字幕（V1–V11）

**窗口**：`titlebarAppearsTransparent` + `.fullSizeContentView`；默认内容 960×150，最小高由字体度量保证（2 行中文 + 1 行原文 + 24）。悬停（追踪区 `.activeAlways`）时 28pt hudWindow 条在 200ms 内淡入：红黄按钮、[`play.rectangle`] 来源名（12pt semibold；“视频字幕 · 来源”在 tooltip、VoiceOver 与窗口标题中）、`ear` 收听图标、`⋯` 菜单（含“锁定字幕位置”）、结束；离开 1.5 秒后淡出；VoiceOver 运行时常显。黄/红问题时右上角常显 10pt 警示符号（白色叹号，黄 `exclamationmark.triangle.fill`／红 `exclamationmark.octagon.fill`，带阅读阴影），点击打开详情浮层。默认位置为距屏幕底边 8% `visibleFrame` 高度，水平居中。

**排版**：原文在上、中文在下（设置可选“中文在上”）。中文文本块最大宽 20×中文字号，每页最多 2 行；原文最大宽 46 个字符（约 46×0.52×字号），每页最多 2 行；两块间距 6pt，水平居中，**整体底部锚定**：中文末行基线距内容底边 12pt，单行时整体下沉。窗口加宽只增加两侧留白。窄窗（< 640）时文本块宽 = 窗口宽 − 48，中文下限 18pt、原文下限 14pt。

**分页**：一页中文约 40 字；断点优先在“，。；？！、”及 `, ; . ?` 之后，向前回找不超过半行；两行均衡换行，第二行不得只剩 1–2 字或单个标点。阅读时长规则不变（原文约 18 字符/秒、中文约 9 字/秒，取较长者，1–6 秒；重复停留一侧不再计时；翻完当前句才切下一句；隐藏/最小化暂停）。有待显句时当前句每页时长 ×0.7（下限 1 秒），先追赶，追不上才淘汰较旧待显句。

**视觉反馈**：翻页 120ms 交叉淡化（两页间留 1 帧空白）；句子还有下一页时中文末尾加淡色“›”（白 45%，增强对比度 70%），中文块下 4pt 画页点（3pt 圆点，间距 4，当前页白 90%、其余 30%；增强对比度 100%／50%），最后一页不显示，数据用 VideoSubtitleView 现有 `pageCount` / `currentPageIndex`。草稿同字号，只有与上一版不同的尾部用白 65% 并在句末加“…”，定稿 150ms 过渡到 100%。丢句时在原文位置显示 1.5 秒“已跳过 1 句”（12pt，白 50%，增强对比度 75%）。字幕落后 > 5 秒时右上角显示黄色警示符号，悬停条显示“字幕落后约 N 秒”（`clock.badge.exclamationmark`）。长静默变暗见第 1 节。空状态在原文位置显示“[`ear`] 正在听 Google Chrome…”（14pt，白 60%，增强对比度 80%；13pt 图标同色；来源取实际名称）。

**字幕样式**（字幕设置里视频专属，三选一，按场景保存）：

1. 贴合玻璃（默认）：窗口背景透明，`NSVisualEffectView(.hudWindow)` 只铺在文字块外接框上，内边距左右 16、上下 10，圆角 10，alpha 为场景不透明度；无文字区域完全透明。不透明度 < 0.75 时叠加描边样式的阴影。
2. 描边：无底板；`NSShadow` 黑 85%、模糊 3.5、偏移 (0,−1)，加 `strokeWidth −3` 黑色描边（同时设前景色以保持填充）。不透明度滑块置灰并说明“描边样式不使用背景”。
3. 实底：每行文字后垫圆角 6、rgba(0,0,0,0.62) 的行块，左右 0.4em。系统“降低透明度”开启时自动使用此样式，不透明度 0.85。

**鼠标穿透**：“锁定字幕位置（鼠标穿透）”在会中菜单栏菜单与悬停条 `⋯` 中。锁定后 `ignoresMouseEvents = true`、不响应拖动，只能从菜单栏解锁；锁定时右上角显示 10pt `lock.fill`（40%，增强对比度 80%，带阅读阴影；VoiceOver help 说明从菜单栏解锁）。未锁定时只有文字块与悬停条响应拖动，透明区域显式设置是否接收点击。锁定状态按场景保存。首次出现在全屏 Space 时提示一次“可拖到画面外，或在菜单中锁定”。

**无障碍**：两个文本区 AX 标签“原文 · 英语”“译文 · 中文”；开启朗读时每条中文定稿播报一次。

## 9. 实现记录

2026-11-06 起，按 W1（令牌与标题栏）、W2（三态文字与视频分页）、W3（时间线与状态带）、W4（视频窗口）、W5（字幕设置）、设置流程分支依次实现，并合入 main，构建号升为 29。未启动应用，下列取舍均未经实机验证。与本规格的差异：

- **电话措辞不声称对方已听到**：已确认读者时，详情浮层与状态带写“你的原声正在送入 Phone”“原声 · 正在送入 Phone”“译音正在送入 Phone”，不写“对方听到…”／“通话对方能听到你”，以保持“Phone 已接收 ≠ 对方听到”。
- **窄窗最短胶囊**：所有本机或未发送状态（恢复中、未发送、电话各态、不可用）都缩成“本机”，视频为“收听”。
- **原因芯片**：原声风险与会议未用 Mic 改写胶囊的同时，问题槽显示原因芯片（“会议在用实体麦”“会议未用 TalkTalk Mic”），以免原因只出现在详情中。
- **会议结束确认**：正文按 TalkTalk 是否接管系统默认输入选择两句之一。会议应用是否跟随默认输入无法观察，因此只是近似。
- **键帽动作与状态带**：
  - 键帽动作：处理／排空时用“开始翻译”；电话读者未确认时一律为“本机试说”。
  - 状态带：Feed 实际播放前的排空写“译音处理中 · 原声已关”，实际播放时才写“译音播放中”。
  - 状态带键帽只显示键；28pt 紧凑状态带没有键帽；修复／详情只留图标（20×20，`wrench.and.screwdriver`／`info.circle`，tooltip 与 AX 为“修复…”／“详情”）。完整状态带中“修复…”为扳手加文字，“详情”只留 `info.circle`。
  - 紧凑或窄窗隐藏的后果说明保留在状态行的 tooltip（“标签 · 后果”）中。
- **云端提示锚点**：一次性云端提示锚定网络图标，问题芯片占位时改锚定胶囊。
- **标题栏高度与图标**：32pt 通过附件视图请求，AppKit 可能保留原生高度，控件按实际高度居中。当前 SDK 没有 `mic.badge.exclamationmark`，使用 `mic.fill` 叠加 `exclamationmark.circle.fill`。
- **光标与淡化**：
  - 我的行的实时原文光标用 voice.translate，对方行按规格用 speaker.remote。
  - 视频翻页为淡出 60ms、空一帧、淡入 60ms，不同时叠化。
  - 悬停条淡出也用 200ms。
- **视频版面**：
  - 贴合玻璃只铺一块，覆盖两个文本块的外接框。
  - 页点限制在内容区内；“中文在上”时，多页句子会让两块间距增加页点高度。
  - “已跳过 N 句”在 1.5 秒内替换原文块，阅读计时不暂停。
- **视频窗口**：
  - 隐藏绿色缩放按钮；警示符号画在内容中，点击区在标题栏尾部预留的 26pt 内，所以视频的“结束”内移 26pt。
  - 透明区域接收点击但不拖动、不动作，真正穿透只在锁定时生效。
  - `⋯` 菜单只有锁定一项；锁定只对视频生效。
  - 悬停条通过隐藏 `NSTitlebarContainerView`（私有层级，按类名查找）实现。
- **全屏 Space 与长静默**：
  - 全屏 Space 无公开 API，按其他应用占满显示器的 0 层窗口推断；提示为窗口内胶囊，不用 NSPopover。
  - 长静默底板取 min(原值, 40%)；只有占位提示时不变暗。
- **时间线**：
  - 列头只描述远端语言。
  - 我的行按本轮首个非空原文排序，60 秒从提交时计；这是内存中的有界阅读窗口，取代旧规则“不建立发言历史”。
  - 字幕重置只清远端句对，会话结束和换场景全部清空。
  - 未得到定稿的非原声轮次以草稿样式保留；“已中止”用 warn 色加 `xmark.octagon`。
  - “↓ N 条新字幕”只在冻结且 N > 0 时出现。
- **断点**：最小内容高度降为按字号计算（F=22 约 101pt），使低于 140pt 的模式可达。低于 140pt 时状态带不展开，自己的实时发言作为最后一行显示。
- **朗读新译文**：同一偏好覆盖远端定稿与视频中文定稿；自己的译文不播报。
- **送达与“未发送”标记**：tooltip／AX 文本以可见字开头再加说明（如“已送入 Phone：不代表对方已听到”“未发送：这段原文没有提交翻译，对方听不到”），原文列与状态带中的标记也有 tooltip；其后的未发送尾巴为 warn 色。
- **减少透明度**：视频改为透明窗口加 0.85 实底行块；会议／电话仍改为不透明背景。
- **字幕设置预览**：
  - 760:480 含 32pt 标题栏。
  - 玻璃用 within-window 混合，模糊预览背景而不是设置窗口后方。
  - 红黄按钮为绘制的圆点。
  - 没有外层卡片：预览放在首个 section 的 footer，因为 macOS 分组 Form 忽略行背景。
  - 预览固定使用减少动态效果，不运行淡化。
- **标签尾部空间**：标题栏胶囊、芯片、键帽动作和状态带标签增加 4pt 尾部空间（`SubtitleStyle.labelSlack`），修复 NSTextField 按固有宽度截断成“…”的问题。
- **设置流程**：
  - 完成引导先进入完成页，不再直接关窗；只选电话时标题为“准备电话同传”。
  - 菜单快速开始需要选来源时打开场景页，而非选择对话框。
