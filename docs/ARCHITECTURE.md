# TalkTalk 架构

本文是当前设计依据。改变模块边界、音频路径或隐私约束时，先在这里记录理由并同步实现。
功能与验收状态见 [remaining-work.md](remaining-work.md)；构建和使用入口见 [README](../README.md)。

## 平台与模块

TalkTalk 是面向 Apple Silicon 的菜单栏应用，部署目标为 macOS 26；Apple 本地翻译要求 macOS 26.4 及以上并安装对应语言资源，因此使用说明采用 26.4+ 作为完整功能要求。SwiftPM 使用 Swift 6.2 工具链、Swift 6 语言模式；界面采用 AppKit 与 SwiftUI，应用本身不链接 MLX。

| 模块 | 职责 |
|---|---|
| `TalkTalkApp` | 应用装配、菜单、设置、引导、字幕与发言 HUD |
| `TalkTalkCore` | 协议、策略、时间、文本检查、状态机与配置 |
| `TalkTalkSession` | LISTEN/SPEAK 流水线、会议生命周期、按键与原声门控 |
| `TalkTalkAudio` / `CAudioCore` | HAL 采集与输出、重采样、环形缓冲、实时 C 回调 |
| `TalkTalkApple` | Apple Speech、Translation、系统声音适配 |
| `TalkTalkCloud` / `TalkTalkCloudUI` | OpenAI 文本翻译、熔断、连接保温、云端设置 |
| `TalkTalkEngineHost` / `engine/` | 私有 Python 进程、安装器、MLX ASR/TTS、流式协议 |
| `TalkTalkVoice` | 声音录入、校准、校验、存储与试听 |
| `TalkTalkDriverSupport` / `Driver/` | 虚拟麦驱动、安装卸载、状态检查与隔离自检 |
| `TalkTalkSettingsUI` | 设置共用组件：卡片导航（`CardRow`、`CardBadge`、`GlobalRow`）与 `ReturnPill`／`FlowInteraction`、流程图（`FlowGrid`、`NodeChip`、卫星、回环）、`PageHero`、`DataBoundary`、`ThumbnailChoice`、`RecordingBanner`、状态词汇（`SettingsStatus`、`StatusGlyph`、`StatusLabel`、`SettingsProblem`）、`IconButton`／`IconMenuButton`、`FactChip`／`FactRow`、`SectionHeader` 与 `.settingsRow` 行样式、ⓘ；字幕窗口的发声胶囊、键帽、`TitlebarControl` 与 `SubtitleStyle` 样式工厂 |

`TalkTalkSession` 通过 Core 协议接收云端和本地引擎，不直接依赖 Cloud、EngineHost 或 Voice。App 层负责把具体实现装配起来。`TalkTalkSettingsUI` 只依赖 Core，App、CloudUI、DriverSupport 与 Voice 用它绘制设置；依赖 TalkTalkSession 状态的部分（`SubtitleStyle` 的语调颜色、`FlowGrid.meeting` 这类按会话状态画图的工厂、`ScenarioBottomBar`）留在 App。组件的文字参数都是已本地化的 `String`，调用方传 `String(appLocalized:)`。

## 界面语言

设置 › 通用提供“跟随系统／English／中文”，保存为 `ui.appLanguage`，默认跟随系统。只看系统首选语言：中文（含简繁及地区变体）使用简体中文，其余语言一律使用英文；用户的明确选择优先。启动时先捕获原始系统语言，再通过进程内 `NSArgumentDomain` 的 `AppleLanguages` 设置原生启动语言，不写系统语言或其他应用偏好。`AppLanguageStore` 保存选择；`String(appLocalized:)` 从线程安全、可观察的运行时读取显式语言包，SwiftUI 同时接收 locale 环境。选择后即时刷新界面、菜单与字幕控件，不重建音频会话，也不通过重置 SwiftUI 身份来刷新。界面语言不改变 LISTEN/SPEAK 语言、告知语、录音稿或字幕示例的语言。

`Resources/Localizable.xcstrings` 保留稳定的中文源键，同时维护 `en` 与 `zh-Hans` 两套翻译。正式打包使用 Swift 编译器的 `.stringsdata` 提取真实格式类型，再由 `scripts/compile-localizations.py` 生成两套 `.lproj/Localizable.strings`；数值插值的 `%lld` 等格式不能用扫描器的通用 `%@` 直接代替。构建拒绝缺失翻译或占位符不一致，smoke 验证英文、中文与数值插值，并在同一进程切换已使用过的键，检查即时更新。权限说明另由 `InfoPlist.strings` 本地化。状态行为使用枚举等稳定事实，不依赖译后文案匹配。

## 设置视觉系统

依据为 [设置视觉系统规格](decisions/2026-11-06-settings-visual-system.md)（2026-11-06 批准，§9.1 的 8 步（12 行，含协调修正共 13 个提交）已落地，实现偏差记在规格各节）。三条原则：每页先给图形，图形承载状态（角标、计时、实线／虚线、灰显）；能不用的文字就不用；“苹果标准”指原生控件、系统材质与 SF Symbols，HIG 不作为删除图形的理由。下文各页条目写具体内容，这里写全窗口共用的规则。


英文使用导航专用短标题：场景为 Meeting／Phone／Video，模型为 Recognition／Translation／Synthesis，隐私子页为 Data／Subtitles／Diagnostics；中文沿用原名，完整用途留在帮助和辅助功能中。导航卡片同宽同高，标题最多两行，以实际内容决定整行高度（最小 64pt），不压缩字号。侧栏英文使用 Models／Privacy，双语均为 190pt，为页面内容留出空间。

流程图只保留实际使用的尾列；超过 64pt 的原声／译音标签移到所属流程行上方，避免盖住首个节点。长节点标题和风险提示最多两行、节点统一增高，备用路径标签可换行。数据去向卡片按可用宽度从图标与内容并排改为标题在上、内容在下，窄容器可整组纵向排列；事实标签保留字号和完整安全语义，必要时换行。全局开关行空间不足时纵向排列。声音录入的步骤标题统一为“录音／Record”，录入稿件和录音行为不由这条标题改变。

- **页面骨架**：侧栏宽 190（原生 sidebar `Label`，图标取 `SettingsIcon.Page`，尺寸由系统决定），窗口标题为页名，页内不再写页名。详情区自上而下为：ReturnPill（只在流程链接跳转后出现）、导航带（`SettingsNavigationBand`：卡片行加一条原生分隔线，没有子页的页只有分隔线，字幕页在场景卡上方另有全局行）、隐私与诊断的录音横幅，然后是页面自己的 grouped `Form`，只有它滚动。Form 第一个无标题分组是主图：讲声音和文字去向的页为 `FlowGrid`，字幕页为预览，数据与隐私为 `DataBoundary`，没有流程可画的通用、术语表为 `PageHero`。主图下最多一行问题（`SettingsProblem.mostSevere`：风险 > 失败 > 警示 > 等待 > 未检查；短句可见，全句在 help）和一行安全事实 chip。之后是节点放不下的控件分组：`SectionHeader` 的 15pt 图标在 22pt 列，标题不超过 4 字，图标与锚定它的节点相同，节点的页内链接滚到该分组并闪一次标题（减少动态效果时不闪）。破坏性分组在最后。只有使用场景页有固定底栏。窗口内容默认 880×640，最小 820×600。
- **导航**：所有子页都用同一种图标卡片行（`CardRow`），不用分段控件，子页里没有第二层导航。使用场景与字幕共用三张场景卡；模型为语音识别 → 文本翻译 → 语音合成（卡间带箭头）；组件为引擎与模型、虚拟麦克风；隐私与诊断为数据与隐私、字幕分析、故障检查；引导的场景选择为多选卡片行。卡片固定在滚动区外，不收起。卡片只选择正在查看或编辑的对象：场景卡只改 `requestedScenario`，不启动、结束或切换会话；修改一个值（语言、样式）用节点 chip、原生控件或缩略图，不用卡片。没有角标即就绪。
- **图标梯子**：符号尺寸只取 `SubtitleTokens.SettingsIcon.Size`，一律 `.font(.system(size:))` 或 `SymbolConfiguration(pointSize:)`，不用随字号变化的文字样式或相对缩放。22：卡片、PageHero 方块、引导 StepTitle；18：流程节点、节点里的应用图标、步骤圆、DataBoundary 面板；15：Form 行首、分组标题、泳道标签，放在 22pt 固定列，文字从 +30 起（状态行与事实行同样缩进）；13：行内状态图形、图标按钮、ⓘ、ReturnPill、菜单栏菜单（菜单字号，默认 13）；11：卡片和节点角标（垫 15pt 圆底）、事实 chip、卫星、箭头、回环；9：链接 chevron 与 chip 里的锁或三角；8：运行圆点；唯一例外是节点 chip 里的应用图标 12。录制视图的倒数（72）和稿子（26）、引导头部的步骤指示（16 放在 30 圆里）是各自的令牌，不属于梯子。例外：侧栏 `Label` 的图标由系统决定尺寸；菜单栏菜单的图标取 `NSFont.menuFont(ofSize: 0).pointSize`（默认 13，与菜单文字同高，规格 §8.1），不取梯子令牌。一种含义只用一种图形（规格 §4）；设置、菜单栏与标题栏用到的图标令牌由 `SettingsSymbolTests` 用 `NSImage(systemSymbolName:)` 核对存在。
- **文字预算**：可见文字只剩控件名、状态词、安全事实和确认弹窗。没有常显的灰色段落、Section footer、装说明文字的折叠，也没有共享的说明段落组件（`SettingsNote` 已删除）；折叠只装数据或图（技术详情、数值、首次连接、驱动详情）。上限：卡片标题与分组标题 4 字，节点标题 6 字（产品名不计），行标签 10 字，状态短句 12 字加动态名称或数值，chip 8 字（安全事实 16 字），help 一句 20 字，ⓘ 弹层 2 句 60 字以内，每个分组最多 1 个 ⓘ、每页最多 3 个，ⓘ 只用于安全、法律与隐私的完整句子。说明的去处依次是：画进图、写进控件或菜单项、help、VoiceOver、ⓘ、确认弹窗。字符串检查只对标题栏与通知短标签限长，这些上限由评审对照规格 §7 各页的“保留可见中文”执行。
- **安全事实例外**：原声／译音、对方听到或能听到原声、已送入 Phone、仅本机、未发送、已中止、本机播放、云端发送、钥匙串、录音、同意与授权等事实（规格 §5.4）始终可见，写成图标加最短文字，不能只放进 help 或改成纯图标。
- **状态词汇**：`SettingsStatus` 只有 ok、warn、risk、failed、pending、waiting、busy、recording；没有 `.info`，`info.circle` 只表示 ⓘ。`StatusGlyph` 只有两种尺寸：行内 13pt，角标 11pt 放在 15pt 圆底；`StatusLabel` 的 ok／pending／waiting 文字为次要色，warn 为警示墨色。
- **VoiceOver 与 help**：每个只有图标的控件都有本地化的 `.help` 与 `accessibilityLabel`；VoiceOver 文本承载的信息不少于被删掉的可见文字。只对 VoiceOver 用户有意义的控件只在 VoiceOver 运行时显示：字幕页的“用 VoiceOver 读出新字幕”由 `SubtitleSettingsModel` 以 KVO 观察 `NSWorkspace.isVoiceOverEnabled`，回调切到 MainActor 后更新；隐藏时保留已存偏好。
- **大字号**：环境值 `dynamicTypeSize` ≥ xxLarge 时只有 `FlowGrid`、`FactRow`、`DataBoundary` 和我的声音页自己的事实行（ⓘ 与 Finder 挂在首个 chip 后）改为竖排或收起标签列（见下文三个场景一条）；其余组件不另做退化。macOS 用户目前不能改这个值。

## 三种使用场景

- **会议同传**：听英语或德语，显示原文与中文；自己选择说中文或英语，再选择合法译音语言并送入会议：中文 → 英语/德语，英语 → 中文/德语。
- **电话同传**：独立使用场景、菜单入口和字幕外观，通过系统 Phone 与 iPhone 使用本人的号码；先准备同传，再在 Phone 拨号/接听，或将界面填写的号码交给 Phone。挂断由 Phone 操作，结束同传由 TalkTalk 操作并恢复输入。
- **视频字幕**：只收听所选应用并显示双语字幕，不开启麦克风、SPEAK 或默认输入切换。
- 场景决定工作方式，来源属于场景。会议页与视频页在流程图第一个节点的来源 chip 上选择应用（自动、已打开的应用及其图标、刷新列表），分别保存选择；同一个浏览器可以用于两种场景，但互不覆盖偏好。Phone 仅属于电话场景。自动选择分别依据麦克风活动或播放活动；明确选中的应用不可用时 chip 带橙色三角、问题行显示“<App> 未打开”，不静默换源。运行中的来源只读（chip 显示锁，help 保留应用全名），结束后再更换。浏览器来源包含该浏览器的其他标签页，不保证只捕获一个标签页；全局采集仅作当前非电话会话显式选择的备用方式。
- Mac 的 Phone（`com.apple.mobilephone`）作为独立来源复用会议同传，与 FaceTime 分开显示。来源归属先采用同 PID 的已知运行应用身份，再回退到 Core Audio 的 bundle ID、父进程与 responsible PID；不因 Phone 正在运行就把共享通话服务或真正的 FaceTime 归给它。Phone 的“音频 › 麦克风”可选“使用系统设置”，复用现有 TalkTalk Mic 默认输入管理；应用识别与真实电话双向音频验收分别记录。
- 所有子页导航都是同一种图标卡片行：使用场景与字幕的三张场景卡、识别与翻译的语音识别 → 文本翻译 → 语音合成（卡间带箭头）、安装与维护、隐私与诊断。卡片行固定在设置详情区的导航带里、滚动区之外，不收起，也不退化成分段控件，子页内没有第二层导航；每页记住上次的子页，切换时滚回顶部。卡片右上角在子页需要处理时显示角标（没有角标即就绪；文本翻译读本页同一份事实：有文字发给 OpenAI 时（运行中会话开始时的方向也算）为 `network`，选了 OpenAI 却没有 key、key 未通过验证或模型下线时为警示，警示占用角标时 help 与 VoiceOver 仍说明已启用 OpenAI；字幕分析记录中、诊断录音中为录音角标）。选页本身不启动或切换运行会话。菜单入口打开各自场景页，移除跨场景的全局来源选择；会中菜单只显示当前来源。电话模式固定绑定 Phone，不沿用或覆盖会议/视频的来源，不允许全局声音备用。准备时先打开 Phone，再建立 LISTEN/SPEAK 与 Feed；无需等电话接通即可显示“电话同传已就绪”，“打开 Phone”独立可用，不随准备状态禁用；号码输入、校验与 `tel:` 转交链路已移除，拨号、接听和挂断都在系统 Phone 中完成。
- 电话模式准备完成即开启本机实体麦采集，并可点按右 Option 开始翻译，不等待 Phone 的通话读者。Feed、系统输入、实体麦和按键状态必须真实可用；明确没有远端读者时采用独立的本地发言就绪判断，不把守卫伪装成已确认，也不修改原声门的读者与输出检查。首次确定的读者状态仅建立基线；之后真实读者出现或消失时，先关闭当前发言并串行取消旧识别、翻译、合成及待播译音，再恢复流水线，最后解除本地发言屏障，避免恢复期间提前显示就绪。清理是短暂屏障，不持续等待读者；递增令牌与会话/流水线身份在清理前、恢复前及完成后隔离过期任务，防止旧事件暂停新流水线或提前解除新屏障。该事件可能是静音、保持、设备切换或通话边界，不用讲话静默或音量推断。用户结束同传或准备失败会拆除会话并恢复输入；长时间无应用音频仍按既有 10 分钟提醒、60 秒后结束规则处理。
- 使用场景页的底栏（`ScenarioBottomBar`，高 56、`.bar` 材质）固定在滚动内容之外。右侧主按钮只用短词：空闲时“开始”（电话为“准备”），开始或结束过程中为进度指示加“准备中…／结束中…”并禁用，运行本场景时为红色“结束”；浏览另一个场景而别的场景在运行时按钮禁用，tooltip 为“先结束<运行中场景>”。VoiceOver 标签用全称（“开始会议同传／准备电话同传／结束会议同传”等），结束的后果在 tooltip（与标题栏结束相同的 `endHelp`）。左侧在会话运行时显示“● [场景图标] <来源> · 12:03”（电话来源为 Phone，只有计时文字在 TimelineView 里），圆点与菜单一致取当前发声状态的颜色（原声绿、译音蓝、警示橙、风险红，视频收听为中性），点按即选中运行中的场景卡；电话另显示“通话不会挂断”；字幕已隐藏时显示橙色“字幕已隐藏”和“显示”。没有运行横幅和描述行。所有设置入口共用 `show` 的前台激活路径，恢复被隐藏或最小化的窗口，并在菜单跟踪结束后按本次请求补做一次前置；窗口保持普通层级，不长期悬浮在其他应用上方。
- 菜单栏菜单的行由 TalkTalkSession 的纯函数 `StatusMenu.rows` 给出，`StatusItemController` 只负责绘制并把命令接到动作；没有“更多”子菜单，也没有说明子菜单，语言选择统一在字幕浮窗和设置 › 使用场景。可操作项配 13pt 模板图，应用信息行使用与其他菜单项一致的单色双对话框图标，软件名与包含构建号的版本同处一行；“退出”不配图。状态 A（引导未完成）：最上方是粗体 `arrow.clockwise.circle`“继续使用引导 · 第 N 步，共 M 步”（`OnboardingState.progress`，与引导头部和通用页同源），打开引导到该步；它代替“Apple 资源待配置”和“组件未就绪”两行；开始项禁用，tooltip“完成引导后可用”。首次启动仍自动打开引导；引导完成后，入口只在 设置 › 通用 › Qwen 在共享引擎中以较低优先级运行，冷启动先等待 ASR 就绪；不可用或识别失败时接管到 Apple，界面显示实际引擎状态。单次解码超过引擎 300 ms 的低优先级期限只说明累积窗口过长，不算识别失败：已读到的内容先定稿，从其后重开窗口，连续 3 次过期才接管。视频没有语音合成争用 GPU，Qwen 假设每 500 ms 读取一次，会议和电话保持每秒一次；句间停顿规则仍按 1 秒的文本更新间隔计算，提高频率不改变停顿分句的门槛。

Qwen 没有时间戳，并且每次识别都在末尾补句末标点，所以窗口末尾的句号不能说明句子结束。视频字幕（`RollingSentenceCommitter`）只相信窗口中间的句号：连续两次假设都在，后面还有至少 3 个词（中文 6 个字符），且不是缩写、小数或后接小写词，这一句立刻定稿，音频窗口不动，后续假设中已定稿的部分用编辑距离对齐后去掉。8 秒强制切窗或解码过期时，末尾句号被去掉，句子接到下一段继续；英文下一段开头被模型大写的普通词改回小写。收听链路请求的定稿保留标点；定稿时只在上一次假设也有的句号处拆句，拆出的尾巴去掉句号，句子继续，直到静音、下一个稳定句号或硬上限收尾。视频字幕不用文字停顿判断句末：Qwen 末尾几个词会滞后，真实网络会议里说话人没停，词数也会静止约 1.25 秒，于是关闭标点停顿，其余文字停顿规则放宽到 2.5 秒，只防句子挂住。早定稿的句子没有音频终点，事件时间取产生它的假设之前一点，既挡住更早的假设，也不挡这个窗口真正的定稿。视频字幕不启用德语回看合并；译文迟到且从未显示过的句子不丢弃，草稿先让位，已显示的定稿则排在其后。会议和电话的窗口与分句不变。

两次假设的一致窗口随频率缩短，已提交的词更可能被后续识别改写；收听链路在最新假设就更长前缀达成一致时采用新前缀，避免草稿停到句尾。按键发言的预览不用这条规则。
原文语言与 ASR 选择可在会话中切换；配置代际隔离旧回调，切换清空旧字幕和待显队列，不重启 SPEAK 或默认输入管理。
LISTEN 的数字检查结果仅保留为元数据供已有诊断使用，不再向字幕正文附加“数字待核”等提示文字；不改变翻译结果或数字校验行为。
LISTEN 定稿继续并行启动云翻译和 Apple 备用，并优先采用按时到达的云结果。同一句、同一语言方向且最终原文完全相同时，既可复用已完成的 Apple 草稿，也可接管仍在翻译的草稿任务，避免取消后重译；接管后的任务不再随下一句草稿取消。二次识别或德语回看改写原文时不复用旧任务，草稿失败则补发原有最终 Apple 请求。停止／切换语言及云结果胜出仍取消对应任务；`mt.apple_reuse` 和 `mt.apple_reuse_retry` 只记录句号、复用类型等元数据，不保存正文。此优化不改变识别分段、翻译截止时间、云结果优先级或字幕阅读节奏。
最终字幕按句配对保留原文和译文。会议和电话保留独立草稿，由 `ConversationTimeline` 把远端句对与自己的按键发言按到达时间合并成一条时间线；保存最近约 60 秒的阅读窗口，最多 24 段、原译文合计约 6,000 字符，只按已定稿行计算，按完整句对退出，始终保留最新一对，已淘汰的句对不再回来。识别代际保证正在识别的远端原文不与另一句的草稿配对。字幕重置（换原文语言或配置）只清远端句对、保留自己的发言；会话结束或换场景全部清空。时间线只在内存中，不写日志。视频使用独立单句呈现：当前原文与中文占用两个固定区域，草稿携带真正提交翻译的原文，定稿在同句同位置替换，不能叠加成第三段；后续句对最多待显两组，按阅读节奏整体前进，积压淘汰较旧待显句，迟到结果不倒退画面。原始 ASR 文字仅在尚无句对时作为原文单独显示，不能与另一句译文配对。短暂停顿不自行清空；视频另有长静默变暗：最后一页阅读时间过后 8 秒既无待显句也无原文变化时，文字降到 35%、玻璃或行块降到 min(原值, 40%)，300 ms 过渡；新定稿、草稿或非空原文变化，以及清空、显示、恢复窗口时立即还原。只有占位提示时不变暗。偏好 `ui.videoLongSilenceDim`，默认开。显示窗口不限制识别、翻译或音频工作，也不作为传给模型的历史。支持字号、拖动与位置保存，不抢键盘焦点。字幕窗口及其详情浮层设 `sharingType = .none`；Apple 文档把 `NSWindow.SharingType.none` 写作 macOS 不再使用的旧常量，只说它会让内容在部分共享方式下不可用，并说明不要用它来隐藏或防止截取内容，开发者论坛也有 macOS 15.4 起 ScreenCaptureKit 仍能录到这类窗口的报告。所以 help 只写“部分共享方式下可能不显示，不作保证”，不承诺屏幕共享或录屏一定看不到；可见 chip“共享屏幕不可见”仍是承诺式写法，是否改词待用户决定（规格 §7.4 实现记录）；实际会议共享与录屏工具的表现需用户安排实测。

视频长句依据 AppKit 的实际字体与逐字宽度分页（`VideoCaptionPager`），固定原文区与中文区不使用记录式滚动或自动跟尾。原文块和中文块每页都最多 2 行，原文只在高度允许时用 2 行。断点向前回找不超过半行，优先落在“，。；？！、”或 `, ; . ?` 之后。两行页取最均衡的断点，标点断点与最均衡点相差不超过 15% 行宽时优先标点。第二行不得只剩 1–2 字或单个标点，过小的末页会回拉断点；行首不放闭合标点，拉丁单词不拆开，除非一个词就超过整行。原译文分别保存阅读位置，较短一侧保持最后一页，较长一侧继续，异步增长不能跳过中间内容。草稿与定稿同字号：草稿中与上一版相同的前缀为白 100%，变化的尾部为白 65% 并在句末加“…”，定稿 150 ms 过渡到 100%。相同或仅追加的定稿保留阅读位置，早期文字或数字修正则在定稿后回到对应修改位置，草稿期间已发生但尚未展示的修正也要保留。每页按原文每秒约 18 字符、中文每秒约 9 字符估算，取较长者并限于 1–6 秒，重复停留的一侧不再次计时；翻完当前句才切换下一句。有待显句时当前句每页时长 ×0.7（下限 1 秒），先追赶，追不上才淘汰较旧待显句；淘汰时在原文位置显示 1.5 秒“已跳过 N 句”（12pt，白 50%，增强对比度 75%）；“用 VoiceOver 读出新字幕”开启时以 low 优先级向 VoiceOver 播报。最旧待显句等待超过 5 秒时，作为外部问题“字幕落后”（`clock.badge.exclamationmark`，detail“字幕落后于声音，正在加快翻页追赶”）进入问题槽，右上角显示黄色警示符号；落后期间芯片固定不变，只在开始或结束落后时更新，宽度不随秒数变化，VoiceOver 只播报一次。隐藏／最小化时暂停翻页，恢复时重新给予当前页阅读时间。字幕分析区分完整句身份与实际可见页，报告中的已显示不代表整句所有页面均已阅读。

视频排版：中文块宽 min(20×中文字号, W−48)，原文块宽 min(46×0.52×原文字号, W−48)；窄窗（< 640）时宽 = W−48。两块水平居中、间距 6pt，整体底部锚定：下方文本块末行基线距内容底边 12pt（由 TextKit 量出），单行时整体下沉；窗口加宽只增加两侧留白。默认原文在上，可选“译文在上”（`ui.videoCaptionArrangement`）。还有下一页时中文块下 4pt 画页点（不再在中文末尾另加“›”）（3pt，间距 4，当前页白 90%、其余 30%），最后一页不显示。翻页先淡出 60 ms，留一帧空白，再淡入 60 ms。视频没有实际原文或译文时不显示窗口，仅来源名、状态和空白文字不能单独露出控制条；首份内容先排版再显示。清空／换语言后重新等待内容，已有字幕的长静默继续变暗；手动隐藏、最小化仍由用户控制。内部空状态保留“正在听 <来源>…”占位，但不凭占位显示空窗口。两个文本区的 AX 标签为“原文 · <语言>”“译文 · 中文”。字幕样式按 `ui.videoCaptionStyle` 保存，三选一。贴合玻璃（默认）：窗口本身透明，hudWindow 玻璃与控制条共用稳定阅读宽度：原文／译文目标块宽取较大者，再加左右各 16pt，限于窗口宽度；横向不随短句逐字收窄，纵向仍包住实际文字并加上下各 10pt（圆角 10，alpha 为场景不透明度）。不透明度 < 0.75 时叠加描边阴影。描边：无底板，阴影黑 85%、模糊 3.5、偏移 (0,−1)，加 −3 黑色描边并保留填充，不使用背景不透明度。实底：每行文字后垫圆角 6、黑 0.62 的行块，左右各 0.4em；系统“减少透明度”开启时强制使用实底，不透明度 0.85。窗口最小高度由字体度量保证 2 行中文 + 1 行原文 + 24，并预留 34pt 控制区（28pt 条 + 6pt 间距）；默认内容 960×184，首次位置在 `visibleFrame` 底边以上 8% 高度处水平居中；内容更新不改变窗口尺寸。

三个场景统一使用悬停控制条，保留既有原生符号、配色、字号、胶囊、键帽、字幕列和底部状态带。指针进入字幕窗口（`.activeAlways` 追踪区）时控制条在 200 ms 内淡入；离开后等待 350 ms，再以 200 ms 淡出，完全淡出后不接收点击。“减少动态效果”时直接切换；VoiceOver 运行时（KVO 观察 `NSWorkspace.isVoiceOverEnabled`），或正文关闭、窗口只剩控制条时，控制条保持显示。控制条使用原生深色外观的实底，不跟随字幕背景不透明度；正文仍遵守原有玻璃／描边／实底与辅助功能取值。显隐只作用于控制，不重排正文。

字幕浮窗保留原生有标题窗口的拖动、缩放和最小化行为。自绘控制条中的图标与文字统一命中所属按钮；窗口仅将可见控制条上按钮的左键事件交给该控件，避开原生标题栏保留区对事件的截获。按下后拖出不触发，隐藏或切换场景时取消未完成点击；空白区和其他事件仍由 AppKit 处理。

视频窗口使用 `fullSizeContentView`，隐藏绿色缩放按钮。28pt 实底控制条与稳定阅读区同宽、水平居中，位于实际字幕框上方 6pt；字幕末行基线仍距内容底边 12pt。控制条显示红黄按钮、`play.rectangle` 加来源名（“视频字幕 · 来源”在 tooltip、AX 与窗口标题中）、只读 12pt `ear` 收听图标（不画胶囊）、问题芯片、`⋯` 菜单（VoiceOver 角色为菜单按钮）和 `stop.circle` 结束图标。文字更新时避免将正在指针下操作的控件移走，显隐不改变分页或字幕位置。本窗口打开的浮层或 `⋯` 菜单会保持已显示的条，但不会让隐藏的条重新出现。黄／红问题时右上角常显 10pt 警示符号（白叹号；warn 黄 `exclamationmark.triangle.fill`，risk 红 `exclamationmark.octagon.fill`；带阅读阴影）：符号画在内容中、不参与命中测试，点击区是标题栏附件尾部预留的 26pt 内不可见控件，携带 AX 标签与说明，点击打开详情浮层；悬停条隐藏时符号本身是 VoiceOver 按钮。`⋯` 菜单与会中菜单栏菜单都有“锁定字幕位置（鼠标穿透）”（`ui.videoSubtitleLocked`，仅视频生效）。锁定后窗口 `ignoresMouseEvents`、不可移动，悬停条不再出现，右上角显示 10pt 白 40%（增强对比度 80%）带阅读阴影的 `lock.fill`，VoiceOver help 说明从菜单栏解锁；只能从菜单栏解锁。未锁定时只有文字块（玻璃框，或描边／实底时文字外扩 16/10）与悬停条能拖动窗口；透明区域接收点击但不拖动、不动作，不会穿透到下层应用。首次出现在全屏 Space 时，窗口内提示一次“可拖到画面外，或在菜单中锁定”（向 VoiceOver 播报一次，增强对比度时加 1pt 描边），6 秒后 300 ms 淡出，记入 `ui.videoFullScreenHintShown`。全屏 Space 没有公开 API，只按其他应用占满整块显示器的 0 层窗口推断，仅读取边界、层级与进程号，不保存、不记录。

会议内容只使用一个浮窗：对方/视频双语字幕与自己的按键翻译反馈在同一窗口显示，共享标题栏、拖动与位置记忆。窗口可拖动边缘调整尺寸，高度用来增加可见行数；保留用户设定的尺寸，内容和状态变化（包括状态带伸缩）只移动窗口内部的分隔，不改变窗口外框。会议/电话的对方译文字号 F = B×clamp(√(W/760), 0.85, 1.30)，再夹到 [14, 1.3B]，原文 max(12, 0.78F)，我的译文 0.86F。视频中文为基础字号 B，只在 640–1200pt 宽度间 ±15% 微调，窄窗下限 min(18, B)；视频原文 max(14, 0.66B)。B 默认会议/电话 22、视频 26。颜色、字号、间距、圆角与动效统一取自 `SubtitleTokens`。背景采用 macOS 原生半透明材质，可调背景不透明度。不透明度 < 0.75 时正文加阅读阴影；“增强对比度”开启时不透明度至少 0.95，并使用高对比颜色与 4pt 色轨。系统“减少透明度”优先：会议、电话改为不透明，视频改用实底行块。三项辅助功能显示设置一起读取，“减少动态效果”时所有过渡直接切换。原声直通只发送声音，不启动自己的按键识别；收听链路应过滤已确认的本机原声回流，不能在默认原声门打开的整场期间停掉对方字幕。

窗口呈现按场景明确区分。会议同传自上而下为标题栏、列头、一条句对时间线和底部麦克风状态带。列头整窗只出现一次：“原文”“译文”；时间线同时保留双方以及之前方向的句子，不用当前远端语言标注整列。当前方向显示在控制条的语言按钮。句对行由三部分组成：24pt 说话人轨、原文 40%、间距 16、译文 60%。行高取两列较大者，顶端对齐，行间 0.5pt 分隔。轨区竖条 3pt（增强对比度 4pt）：对方为 speaker.remote，我为 voice.translate；同一说话人的连续行相连，一段的首行放 16pt 标记（对方 `person.wave.2.fill`，电话 `phone.fill`，我 `person.crop.circle.fill`；`mic.fill` 在此界面只表示原声）。我的行有 meRow 底色并在译文末尾显示送达标签，悬停整行加亮。原文高度超过译文 2 倍时截断，末尾为“…”加 `chevron.down.circle`（tooltip 与 AX 为“展开原文”），点击就地展开。正文三态：正在识别的原文为 sourceLive，句末带不闪烁的静态竖条光标；译文草稿与定稿同字号、同字重，用 draft 色，末尾“…”，左缘有 2pt 竖条；定稿时竖条消失，150 ms 过渡，不回流。字幕正文不标注译文来自云端还是 Apple 备用，收听翻译的降级状态在菜单栏显示。未提交短尾显示为 warn“未发送”标记加未发送文字。送达标签依据实际播放结果：会议为“已送出”（只画 `checkmark.circle.fill`，文字在 tooltip 与 VoiceOver）／“未发送”；电话为“已送入 Phone”（仅 Phone 读者已确认）、“仅本机 · Phone 未接收”或读者断开时的“已中止”。处于风险或不可用时的播放不算送出。行内标记都有 tooltip，tooltip 与 VoiceOver 文本以可见字开头再加说明，不声称对方已听到。断点：内容宽 < 520 时句对上下堆叠（译文在上）；内容高 < 260 时状态带收成 28pt 单行（图标、短标签、迷你曲线，无键帽；修复／详情只留 20×20 图标；隐藏的后果说明在 tooltip 中）；内容高 < 140 时只保留时间线最后一行，状态带不展开，自己的实时发言作为最后一行显示。最小内容高度由字号决定（F=22 时约 101pt）。空状态：会议居中显示“正在听 <来源>…”（与视频同一写法）；`meetingSilent` 时显示可点击的“暂未听到对方声音”，前置与标题栏芯片和菜单提示行相同的 `waveform.slash`（收听中为 `ear`，电话为 `phone`），tooltip“查看详情”，点击打开详情；此时标题栏的灰色“未听到对方”芯片让位（详情中仍列出），有行或关闭字幕后再回到标题栏。电话空状态只显示“等待对方字幕…”；拨号、接听与挂断写在 Phone 按钮和结束按钮的 help 中。第一条字幕到达后，占位提示 120 ms 淡出。每个句对行是一个 VoiceOver 元素。“用 VoiceOver 读出新字幕”（`ui.announceNewTranslations`）默认关，设置中只在 VoiceOver 运行时显示；开启且窗口可见时，每条远端译文定稿和视频中文定稿以 medium 优先级播报，草稿和自己的译文不播报。只有变化的行会重建，通常是最后一行。

麦克风状态带空闲高 48pt，上缘 0.5pt 分隔。纯状态行、波形、状态操作及该行分隔线随控制条显隐；固定占位、时间线阅读位置及下面的本人实时原译文保持不变，不能隐藏整个状态带或让字幕随悬停跳动。左侧为状态图标、13pt semibold 状态文字（发声状态色）和 12pt 后果说明；中间是开始提示与弹性 24pt 曲线带；右侧只在原声风险或音频不可用时放修复／详情按钮，不再重复标题栏的键帽。开始提示“点按右⌥翻译你的发言”只在第一次自己的发言之前出现（`ui.dockStartHintDone`，试说也算）。状态文字随发声状态变化：原声为“原声 · 对方能听到你”，翻译收音为“翻译中 · 原声已关”，按下未松开为“松开右⌥确认”。译音尚未实际播放时为“译音处理中 · 原声已关”，Feed 实际播放时才显示“译音播放中”；恢复中显示“正在恢复原声…”，未发送为“未发送 · 对方听不到你”。原声风险使用红 18% 底、左缘 3pt 红条和“修复…”（`wrench.and.screwdriver` 加文字）；音频不可用使用 warn 15% 底和只有 `info.circle` 的“详情”按钮（tooltip 与 AX 为“详情”）。增强对比度时曲线为状态色 85%、线宽加 0.5pt。这两个按钮都打开详情浮层。会话刚开始、音频与按键监听尚在准备时（`MeetingAudio.preparing`，最长 3 秒，`SpeakStartupWait`）胶囊与状态带为“未发送 · 对方听不到你”，没有键帽动作；超过 3 秒仍未就绪，或就绪后再失去，才显示“音频不可用”。电话按 Phone 读者分态：已确认的原声写“原声 · 正在送入 Phone”，不声称通话对方已听到；未确认时胶囊保留“本机试说”，底部按实际阶段写“本机收音中 · Phone 未接收”或“本机译音处理中 · Phone 未接收”；仅本机实际播放时底部写“本机译音播放中”，原因由“Phone 未接收”芯片与详情说明，不重复铺在底部。本机就绪而读者未确认时为“未接入 Phone · Phone 尚未接收音频”；这不判断电话是否接通。已确认 Phone 接收且实际播放时，底部仍为“译音播放中 · 原声已关”，tooltip 与播报用“译音正在送入 Phone”；已完成行的送达标签保留“已送入 Phone”。读者断开期间显示“当前发言已停止 · 等待 Phone”。发言态从翻译锁存开始，到待处理工作结束后再过 3 秒，状态带在 180 ms easeInOut 内展开到 min(内容高 34%, 160pt)。展开时底色为蓝 10%、左缘 3pt 蓝条，按时间线的列显示我的实时原文与译文草稿。收回时本轮作为“我的行”插入时间线；最终结果未到的非原声轮次以草稿样式保留。状态和电平更新不重建正文。电话同传复用时间线、状态带和标题栏；没有 Phone 输入读者时，也必须在实体麦实际开启且本地链路可用后才显示“电话同传已就绪”。本地就绪不表示电话已接通或对方正在接收声音。三个场景独立记住尺寸、位置、基础字号和背景不透明度；旧的共有偏好仅继承给会议场景，显示字幕总开关仍共用。场景仅由会话/引导入口决定，切换设置标签或收到迟到的音频状态不得切换窗口场景。

时间线默认跟随底部。手动上翻后整条时间线一起冻结，只额外保留一份最新显示快照，并统计冻结后新增的定稿数。N > 0 时，在时间线底部、状态带上方 8pt 处居中显示 `arrow.down` 加“N 条新字幕”的胶囊（tooltip“回到最新字幕”）；点击或滚回底部恢复跟随。冻结不暂停上游处理、不累计无限历史；新一轮自己的翻译发言或会话重置立即解除冻结并替换快照。字幕分析只记录实际显示的行，冻结期间不记。视频保持字幕的即时更新行为。

会议和电话在内容区使用固定 32pt 高度的控制条，右侧固定顺序为 `[发声胶囊 ⌄] [问题/通知芯片] [右⌥ 键帽 + 动作] [Phone ↗] │ [stop.circle]`，隐藏的控件不占位。控件沿用现有样式并在条内居中，原生标题栏容器隐藏。左侧依次是原生红黄按钮、统一场景图标（非无障碍元素）、13pt semibold 场景名和 13pt 白 60% 的“ · 来源”。原生标题隐藏，但保留给辅助功能。标题栏控件接受首次点击、不拖动窗口、指针为箭头；标签预留 4pt 尾部空间，避免短词被截成“…”。键帽动作“开始翻译”沿用键帽后的 `translate` 图标；结束本次收音改为“完成发言”文字，不再画 `stop.fill`。窄窗隐藏文字时 tooltip 与 AX 仍明确“右⌥ 完成发言”，并说明译音播完后恢复原声、同传继续；胶囊已写同样文字时键帽不重复（`TitlebarKey.drawsAction`）：按下未松开只画按下态键帽（胶囊为“松开确认”），电话本机试说画开始图标；“未接入 Phone”时的“本机试说”保留文字（按下只是本机试说）；窗口宽 < 560 时只留键帽。翻译中键帽为蓝色实底。电话的“Phone ↗”（`arrow.up.forward.app`）是唯一的 Phone 入口，状态中不再出现 phone 图标；`phone.arrow.up.right` 只表示“已送入 Phone”。窄窗按 `TitlebarCompaction` 依次退让：来源名截断、键帽动作文字、Phone 文字、芯片文字，最后胶囊缩成仍能辨认的状态（原声／译音／本机／恢复中；视频为收听），风险态最短为“对方听到原声”。控制条显示时胶囊不因窄窗被隐藏。三个场景结束整场一律使用现有 `stop.circle` 图标，默认白 70%，悬停变红；结束（标题栏与菜单）立即结束，不再确认。AX 标签为“结束会议同传／结束电话同传／结束视频字幕”。tooltip 与 help 写实际后果：会议为“结束会议同传：不会退出会议；TalkTalk 停止收听和译音”，电话为“结束电话同传：通话不会挂断；TalkTalk 停止收听和译音”；TalkTalk 接管系统默认输入时补充“并还原系统麦克风”。视频为“结束视频字幕：停止收听和翻译”。会议应用与 Phone 是否跟随默认输入、对方随后听到什么不可观察，不再作此承诺。字幕窗口允许在应用处于后台时显示 tooltip。任何原因的结束（用户、自动、失败、睡眠后、引导演示、退出）在停止开始时（`MeetingEvent.stopping`）一步移出窗口，不经过仅标题栏的中间帧，停止与清理在后台继续；可见的会话窗口离开时向 VoiceOver 播报“<场景>已结束”。会话结束后窗口不再因通知重新出现（`SubtitleWindowPresence`），只有新会话会重新打开它。三个场景都在会话 `.started` 时才出现，且直接是最终尺寸；电话的准备进度只在菜单栏显示，不再先出现只有标题栏的一条。会话之外 `issueSlot`／`issueChips` 为空，迟到的通知与一次性消息（`meetingEnded` 清除）不会交给窗口。输入还原失败或等待还原只在菜单栏显示，成功还原不再单独提示。仅标题栏模式只用于会话中关闭字幕。电话仍由 Phone 挂断。场景图标三处统一：会议 `person.2.wave.2`、电话 `phone`、视频 `play.rectangle`。`mic.slash` 只用于原声已关和不可用；原声风险用 `mic.fill` 叠加 `exclamationmark.circle.fill`（0.72×，周围清出 1.5pt 空隙），因为当前 SDK 没有 `mic.badge.exclamationmark`。`speaker.slash` 只表示什么都没发出去（未发送、未接入 Phone）；声音只在本机（本机试说、仅本机、本机播放、“Phone 未接收”）用 `laptopcomputer`；重新连接与音频重启用 `arrow.triangle.2.circlepath`；“已中止”用 `xmark.octagon`，`stop.circle` 只给用户的结束操作。标题栏描边、虚线、分隔线与次要文字使用带增强对比度取值的 control 令牌；自绘控件有按下态，并向 VoiceOver 报告停用状态。视频警示符号始终以三角（warn）或八边形（risk）区分。三个场景控制条均按上文悬停显示；底部保留既有状态带与本人正文，不增加另一条操作栏。关闭全部正文时只保留常显控制条，不覆盖已保存的阅读尺寸。场景切换会重置旧文字与冻结状态，字号变化保持阅读位置。

HUDModel 输出两个独立属性：`voiceState` 由当前发声模式直接得出，不参与问题竞选；`issueSlot` 按问题 > 通知 > 信息 > 云端说明排序。两者在标题栏并列显示，互不覆盖。只有 `remoteHearsYourVoice`、`meetingNotUsingMic` 和 `unavailable` 改写胶囊本身；前两者同时在问题槽显示原因芯片（“会议在用实体麦”“会议未用 TalkTalk Mic”）。胶囊：原声为绿底；翻译收音、处理与播放为“译音”蓝底；按下未松开为“松开确认”蓝描边；恢复中为“原声已关”；本机就绪或未发送为虚线描边。原声风险为红底，保留明确的风险文字并随控制条显隐；收起不清除问题；音频不可用为 warn 底。电话的绿色“原声”要求真实原声门开启且 `phoneInputIsConfirmed`；否则显示“未接入 Phone”或“本机试说”（虚线）。Feed 在播但读者未确认时显示“仅本机”，并加芯片“Phone 未接收”。读者断开、清理屏障期间显示“正在重新连接 Phone…”（`MeetingAudio.phoneReconnecting`）。视频只显示只读 `ear` 图标，tooltip 与 VoiceOver 为“收听中”。芯片文字不超过 10 个单位、通知不超过 8 个（汉字、拉丁词或插值各计 1），由 `scripts/check-strings.sh` 对 `titlebarLabel`／`noticeLabel` 检查。完整句子进入详情，`show()` 不再按长度分流。问题芯片在控制条显示时保留到事实消失，150 ms 淡入；通知为白 28% 描边，4 秒后 300 ms 淡出。`meetingSilent` 显示灰色“未听到对方”；视频没有人也没有会议，静默芯片为“暂无声音”“长时间没有声音”（`waveform.slash`，后者的说明写明即将自动结束及菜单“继续收听”），自动结束通知标题为“视频字幕即将结束”。云端隐私说明常驻 16pt `network` 图标加 6pt 蓝点，会话开始时以 transient 浮层自动弹出一次，不抢焦点；问题芯片占位时锚定胶囊。详情浮层宽 320，使用 NSPopover 原生 darkAqua 材质，设 `sharingType = .none`（不保证不被共享或录屏，见 LISTEN 一节末尾）；打开设置窗口的按钮带“…”与 `gearshape`。顶部是 24pt 胶囊加一句后果；电话写“你的原声正在送入 Phone”或“译音正在送入 Phone”，不声称对方已听到。其后是“右⌥ → 动作”（键空闲时再加一句“再点按一次完成发言；译音播完后回到原声。”）、问题完整说明（`detailChips`：顶部后果已说的“Phone 未接收”“会议未用 TalkTalk Mic”不再重复）、活动事实、云端说明与操作，以及问题带来的设置入口；没有问题时不再放通用的“打开设置…”。详情与云端说明浮层使用原生 transient `NSPopover`，点击外部或按 Esc 关闭，不设手动“关闭”按钮；普通 tooltip 随鼠标移开消失；输入电平不重建详情或正文；关闭详情不会清除持续问题。胶囊的 VoiceOver 标签为一行（如“发声：原声，对方可听到”），完整说明在 help；发声模式类别切换时以 high 优先级播报一次短句。新的首个问题或通知芯片以完整句子播报一次（risk high、warn medium、通知 low），与胶囊同时变化的风险芯片和“Phone 未接收”不重复。电话设置页与菜单也复用 `VoiceState`。

会议和电话仅在状态带中间的 24pt 曲线带显示一根完整起伏的平滑曲线：峰值振幅 10，颜色为发声状态色 55%。原声和翻译收音为实线，按下未松开为描边态，译音处理或播放时为 1pt 虚线，恢复中、未发送、风险和不可用时没有曲线或收平。真实 RMS 沿用原映射控制振幅，低于 −50 dB 收平，采集关闭或超过 250 ms 无有效输入时移除。曲线不等待 ASR，不表示识别完成或远端送达；窄窗状态带用迷你曲线。曲线不随文字滚动，不自行动画；系统减少动态效果时以静止线条的透明度反馈；窗口隐藏或不在屏幕上时停止绘制。视频字幕不显示波形、不启用麦克风。播放活动以实际 Feed 开始消费至段落结束为依据，与收音并行，不把排队或识别预览当成播放。曲线是透明叠加层，保留现有 NSVisualEffectView glass 材质、按场景保存的背景透明度及系统减少透明度优先逻辑。

三个场景都支持原生黄色按钮最小化，红色关闭只隐藏字幕窗口；两者不切换字幕偏好、不停止采集、翻译、译音或右 Option，仅停止不可见曲线绘制。新字幕、迟到提示和状态变化不得自动恢复窗口；菜单栏“恢复字幕窗口”或 Dock 显式恢复现有阅读视图、尺寸和位置。菜单栏应用在持有原生最小化窗口期间保留 Dock 激活能力，关闭设置不能移除恢复入口；新会话才重置上场的隐藏或最小化意图。会议和电话的远端原文/草稿仍最多每 500 ms 合并显示一次；视频字幕的草稿已由上游限速（每句最多每秒两次），内容变化时直接显示，只有无句对时的原文占位按 500 ms 合并；定稿遵循原有阅读节奏；状态和曲线更新不重建发言正文、不改变手动滚动位置或阅读区分配。

## 场景语言与字幕方向

语言选择只有两个可编辑入口：实时字幕浮窗控制条的语言对按钮，以及设置 › 使用场景的对应流程图。浮窗弹层使用 `SceneLanguageEditor`；设置不增加独立语言表单或卡片层级，沿用现有 FlowGrid 节点与语言 chip。视频“应用声音”节点选择原文语言，“双语字幕”节点选择译文语言并提供交换；会议／电话“对方”节点选择原文语言，“双语字幕”节点选择译文语言并提供交换，“我说”节点选择发言源语言，“对方听到译音”节点选择合法目标。“双语字幕”节点不再跳转到样式页，不显示导航箭头，只有语言与互换控件可操作；样式从左侧“字幕”进入。菜单栏不再有语言子菜单；模型页面只读显示摘要并导航到对应使用场景。设置 › 字幕负责随实际语言变化的预览、字号、背景、排列与样式，不承担语言配置。

会议、电话、视频分别保存完整 LISTEN 源/目标（`meeting.listen.*`、`phone.listen.*`、`video.listen.*`）。首次迁移从旧 `listen.remoteLanguage` 复制各场景的源语言并保留中文目标，之后互不影响；编辑非活动场景只更新该场景，不能重启正在进行的收听。三个场景的 LISTEN 均支持 zh↔en、zh↔de、en↔de 六方向；例如对方说中文时，可选英语或德语字幕。会议与电话各自还保存原有 SPEAK 四方向。视频不开启麦克风或语音输出；源和目标必须不同，交换一次提交整个语言对。

完整方向贯穿 ASR hint、Apple 草稿及备用、云提示与术语、数字检查、预览和阅读节奏；视频分页宽度分别使用源语言和目标语言的度量，会议／电话的译文保留时间按中文 9 字／秒、英德 18 字符／秒计算。中文源按字符推进草稿与停顿判定，同时保留原始英文术语空格。中文部分回声使用相邻双字片段匹配，需至少三个不同片段作为文字证据，保留原有声学／播放窗口与远端 VAD 条件；常见短回复不单凭文字命中而丢弃。浮窗语言按钮在窄窗退为图标，完整方向保留在 tooltip/VoiceOver；弹层开启时保持控制条显示。语言变更取消旧代际识别和翻译，重置原译文、视频 cue 与分页；仅更换目标语言也走完整切换。旧请求在进入切换前检查取消和配置代际，空闲时改预设不操作已结束的 session。

## SPEAK：实体麦到会议输入

源语言由用户显式选择，中文可译英语或德语，英语可译中文或德语；不做自动语言检测，不承诺任意中英混说，也不提供德语输入。会议和电话各自保存源/目标语言（会议沿用 `speak.targetLanguage`，电话为 `phone.speak.*`）；变更源语言时保留仍合法的目标，否则默认中文→英语、英语→中文，原子更新整个语言对。场景卡只编辑该场景，运行会话始终使用自己的场景配置；视频没有 SPEAK。

Qwen 主识别、Apple final 备用和 Apple 实时预览均接收同一源语言；翻译 session、提示、术语、数字检查和 Apple 备用按完整方向运行。语言或识别引擎变化走原有串行停止/重建路径，先关闭原声门并清理待识别、译音、预览及本轮上下文，旧代际结果不能更新新会话。系统 TTS 选择已安装的 zh-CN/en-US/de-DE 声音；“我的声音”继续复用原有 conditioning，并把目标语言显式传给引擎，不改写已有声音档案。中文目标允许汉字、短专名和数字，过滤元话语；中文按字符估算时长并保留中文标点。初始 4 字/秒是保守估算，不是用户中文声音的实测拟合。

```text
实体麦 → MicCapture → MicIngest / VAD / clip cutter
原声：PassthroughGate → PassthroughStage → ringP → Feed → TalkTalk Mic → 会议应用
翻译：ASR → MT → 文本检查 → TTS → ClauseQueue
                                  ├─ ringO → 同一个 Feed
                                  └─ ringO2 → Monitor → 耳机自听
```

会议默认发送实体麦原声。右 Option 改为点按开关：第一次干净点按开始翻译收音，再次干净点按结束，等待采集尾段、识别、翻译、合成及待播译音全部排空后，才自动恢复原声。物理按下仍立即关闭原声，干净松键才确认切换；组合键不触发切换。翻译锁存期间无需持续按键，正常打字和鼠标操作不会结束收音；系统、设备或权限故障会取消锁存，不自动恢复翻译。两次快速点按仅表示正常开始与结束，不再使用旧的双击清空规则。此开关切换发言方式，不是麦克风静音；原声模式仍持续采集。
原声与译音互斥；恢复依据真实 gate、流水线 busy 和播放边界，不能只按 UI 状态或 key-up 判断。会议静音使用会议应用的按钮。
状态展示一次读取按键、待处理动作、流水线和原声门的快照。健康链路在译音排空后、下一次硬件轮询开门前显示普通的“正在恢复原声”，不能误报音频故障，也不能提前声称已发送原声。该判断要求真实采集及 Feed 就绪、硬件轮询未超过现有 lease；设备、安全输入、未知状态等失败仍立即提示。这里只修正展示，不改变原声门的开关、续租或恢复时机。
稳定文本负责切句，完整可修订假设负责预览。当前音频片段上限为 4.5 秒；短尾未提交时显示为 warn“未发送”标记加未发送文字，不能冒充成功翻译。
完整短回应有保守的提前提交路径：仅匹配“好的／谢谢／没问题／Thank you”等明确完整回应的闭集，并要求单一句末标点、同段完整假设与稳定前缀一致至少 300 ms、识别覆盖最后语音、至少 0.4 秒有声及 500 ms 实际尾静音。1 ms 内硬件／重采样时间戳缝隙可容忍但不计作静音；恢复讲话、预览修订或跨段回调不能沿用旧稳定证据。切点只落在已捕获的静音内，保留原 250 ms 尾音。一般句子、数字、专名、缩写及未完句不放宽原门槛。短回应仍把完整 PCM 交给原最终 ASR，不直接翻译预览；和短 release 尾段一样，识别提示保留术语但不带上一整句，以防短录音被诱导复读。该路径仅新增 `shortReply` 与 `boundary_wait_ms` 元数据，记录选定音频边界到提交的等待，不保存文字或录音。
自己的发言在状态带中实时显示，收回后作为“我的行”进入同一时间线，与远端句对共用有界阅读窗口。排序按本轮首个非空原文的到达时间，60 秒从提交时计；这是内存中的有界阅读窗口，不写日志或磁盘，不作为模型历史。显示裁剪只作用于文本快照，不删除待识别/翻译/播放任务。已结束但没有识别结果的片段不能阻断后续原文或预览。原声模式不显示草稿；迟到的定稿或送达变化会更新已提交的行。
Feed 的第 1 声道送会议 Mic，第 2 声道只送 Test Mic；自检不能借第 2 声道向真实会议发声。

## 实时音频与生命周期约束

- 实时回调在 C 中运行，不分配内存、不持锁、不做文件、网络或日志 I/O；通过有界环和原子状态与 worker 交换数据。
- 采集时间戳来自音频回调，必须与实际写入帧配对；丢帧和溢出不能造成时间错位。跨线程保留原 host time，不能用 worker 到达时间代替。
- 预录 floor 是实际采集时间的硬下限；按键前已发送的原声不能再次作为翻译预录。ring 的容量不等于允许读取的历史范围。
- 原声只能经过 typed gate → PassthroughStage → ringP → Feed；短租约、设备事实、安全输入和按键组合共同守门，过期或未知状态不放行。没有控制 socket 遥控原声入口。
- 外放模式保留远端 VAD 重叠与回声检查；覆盖不足返回未知，不能记为“无远端语音”或“无回声”。
- HAL listener 注册和移除使用独立 control queue，不在其投递回调队列上等待移除。
- 驱动 0.2.3 起，TalkTalk Mic 在构造并首次公布到 HAL 前即保持 `CanBeDefaultDevice=true`，能力值在设备生命周期内稳定；`ttmm` 只表示会话状态，不再修改可选能力。Mic 仍只在 Feed 有客户端或 Mic 有 IO 读者时列入设备清单；应用空闲但保留 Feed 时也可见，结束同传只恢复输入，不等同于退出应用。两者均消失后经过 5 秒宽限移除。正常退出先还原系统输入、释放 Feed，读者也释放后才按宽限移除；仍有读者或异常退出的行为须单独验收。
- App 在设置界面与音频初始化之前启动同一个系统输入 tracker/guard，尽早保留原实体输入；HAL 快照先读取默认设备及其信息，再枚举设备。无会话、无恢复记录但默认输入落到 TalkTalk Mic 时，现有守卫取得管理锁后重新读取快照，写回前再次核对模式、恢复记录和当前默认 UID，避免依据旧观察覆盖新状态。会话仍显式写入 `ttmm=1`，不把始终为真的能力值当作会话已开启；驱动层不计为独立保护。该守卫不能区分用户手选与 macOS 自动选择，也不能提供 HAL 原子比较交换保证；瞬时切换风险及正常退出恢复都需真实验收。默认输出不受此路径修改。
- 系统设置实际可见性、HAL 清单/默认输入和 Phone 实际读帧分别验收。构建 23 / 驱动 0.2.3 已在系统设置 Input 始终打开的条件下通过本机验证：App 空闲时 Mic 自动出现但保留内建默认输入，准备时选中 Mic，结束同传恢复内建输入，正常退出约 5 秒后 Mic 从 HAL 与界面移除，重开 App 自动重现且不抢默认输入，输出保持不变。构建 21/22 的通知方案失败记录保留在[历史验证记录](validation-history.md)。此结果只验证本机设备生命周期，不表示 Phone 或远端已收到声音；真实电话送达按用户要求另行验收。
- `SpeakOutput`、环、Feed、Monitor 和输出 worker 属于应用；`ClauseQueue`、任务账本和翻译上下文属于一次会话。停止时先取消生产者并拆除输出，再复位缓冲。
- 音频服务重启按关门、detach Feed、suspend Monitor、复位本场队列、恢复 Monitor、按需挂回 Feed 的顺序处理；挂起时延后恢复，不重播旧尾巴。
- 会议模式按当前音频设置自动接入默认输入；停止同传或正常退出应用时自动还原，不再弹出“现在/稍后还原”的选择。仍尊重输入管理所有权和用户已经手动切换的设备；无法还原时保留恢复记录并显示具体修复入口。异常退出继续保留守护恢复路径。应用永不更改系统默认输出。
- 引导试说复用正式 Feed，不启用默认原声；必须有确认的可听耳机且没有 Mic 读者或活动会议。读者出现、锁屏、睡眠或路由失效即停止。

## 引擎、翻译与播放

场景启动先等待设置模型已有的异步密钥存在性查询，再启动原有模型目录后台刷新。创建会话云后端时，在同一次 MainActor 操作中读取最新的已知存在状态，避免后台目录刷新读取钥匙串内容时，主线程再次调用 `SecItemCopyMatching` 检查存在性而争锁。此复用只有内存中的存在／不存在元数据；未知时仍走原查询，实际网络请求仍逐次从钥匙串读取密钥。App 内保存／删除沿用原查询代次保护；直接从外部修改钥匙串不主动刷新存在状态，真实读取失败仍按原规则回退。`cloud.prepare` 和 `listen.prepare` 记录各准备阶段的耗时，不记录密钥、原文或译文。

视频使用 Qwen 识别且引擎需要冷启动时，通过同一个 `EngineProcess` 请求 `--asr-first`：角色、模型、GPU worker 和 HTTP 协议不变，先完成原 ASR 加载及预热，再报告其就绪；原通用 TTS 预热以 P3 分步任务执行，持有既有解码器所有权并允许 ASR 在步间运行。预热的参考、文本、种子、帧数和间隔完全保持原值。TTS 的 health 状态在预热完成前为 loading、失败为 failed；声音身份／构建／加载／试听／合成／相似度操作均等待同一进程的 TTS ready，准备中的等待不计为合成流停滞。取消、进程替换与重启有代际隔离；后台 TTS 预热仍受从进程启动起算的原 readyTimeout 约束，就绪／失败即撤销期限监控，超时沿用挂起恢复，不能用长步骤豁免无限等待；ASR 加载失败沿用 Apple 备用。该启动意图仅由冷启动的首个请求确定，运行中不改启动顺序；崩溃重启保留意图，后续普通冷启动恢复默认。会议、电话及普通引擎启动仍按原顺序预热。`listen.prepare` 分别记录识别和翻译准备耗时，不含正文，也不把翻译准备闭包返回等同于翻译成功。

开发环境与用户安装相互独立：`scripts/setup-dev-python.sh` 按同一 pins 下载校验解释器到仓库 `.build/dev-python`，创建 `.venv` 并按 App 的两份锁文件及哈希安装依赖，不下载模型。`.python-version` 由 gen-pins 同步；`check.sh` 和 `build-app.sh` 先做离线环境预检，再显式使用项目 Python，并向 Python 辅助检查传递 `TALKTALK_DEV_PYTHON`。缺失或过期时明确要求 setup，打包不会因此消耗构建号；安装清单测试也不再借用 App 的解释器。setup 的 `--check` 只读版本、路径及包元数据，不初始化 MLX/Metal。

Python/MLX 在独立进程中运行，通过仅本机 HTTP 与每次启动的认证 token 通信；模型、私有 Python 和 venv 位于 bundle 外。当前推荐普通 GIL CPython 3.14.10（python-build-standalone 20261026），App 携带引擎与安装器并自动部署到 Application Support；启动显式使用私有 venv 的解释器、隔离参数和重建的环境，不依赖系统或 Homebrew Python。依赖锁的解析目标从 TT_PY_VERSION 推导；现有依赖版本及锁散列可保留。安装记录中可比较的较旧同 major Python 显示“可更新”且仍可运行，缺失／未知旧元数据沿用既有锁、API 和文件兼容规则，不要求已安装的较新版本降级。一个 GPU worker 按 TTS、SPEAK ASR、LISTEN ASR、后台工作的优先级调度。
默认“标准”配置使用 Qwen3-ASR-0.6B 与 Qwen3-TTS-1.7B-Base。本地资源只提供三个可选预设：Max 为 TTS 1.7B＋ASR 1.7B（约 5.6 GB 模型文件），标准为 1.7B＋0.6B（4.1 GB），轻量为 0.6B＋0.6B（3.0 GB）。这些容量不含运行时，也不是运行内存保证。旧 raw ID compact16 保留读取和 CLI 兼容，显示“仅语音合成”，不再作为新的资源选项；其 TTS 0.6B 保留不动。

语音合成内页只提供已安装可用的本地 TTS 选择，未安装的 Qwen／Ming 型号留在“安装与维护”下载，完成后才进入下拉列表。当前 active 模型即使缺文件仍保留显示及修复入口；空列表禁用并链接到语音资源。选择已安装的模型执行角色级切换；运行会话、录音、试听或维护期间禁用。安装器验证文件并用原 ASR 配置完成 smoke 后，原子更新 `roles.tts`；失败或取消保留旧选择。原 Qwen 模型文件、ASR 型号／revision、识别偏好及翻译设置保留。Ming 使用相同私有 Python／MLX 进程与既有 TTS 协议，默认配置仍为 Qwen。已下载模型可通过 `--model-source` 校验导入到 Application Support 的标准模型目录，无需再次下载；Ming 的 native CAMPPlus 权重有独立固定来源和散列，随模型一起验证。只有 TTS 的旧安装切换为 Ming 后仍沿用 Apple 识别，不因自定义组合而开启 Qwen ASR。

Ming 适配器在既有 GPU 调度线程逐 latent 让出执行权；完成一个文本片段后整体解码、重采样为 24 kHz Float32 单声道，再按不超过 160 ms 的 PCM 块交付原播放队列。生成中的真实 latent 进展使用既有 progress 帧，避免首段合成被误报为停滞；取消和播放缓冲上限继续由原调度器处理。Ming 不使用 Qwen 专用 codec echo／loop 检查和前句 codec conditioning；保留音频时长、短输出及完成检查。Ming 的真人参考、逐字稿和 native CAMPPlus 声纹仅在本机处理，初始种子固定为本轮试听通过的 20261107。已有识别、翻译、字幕、原声门、ClauseQueue、PlayoutStage 和虚拟麦音频路径不重构。

安装状态按 install.json 的 active roles 归类，额外下载但未选用的模型不改变档位；旧 max 的 1.7B＋0.6B 显示为标准，读取不改写记录或模型。合法但不属于预设的组合显示为自定义组合，不影响原有兼容性与文件校验。独立选择合成模型形成自定义组合时，安装与维护显示实际合成模型及识别配置保持独立的提示；模型列表以“当前使用”标记区分 active role 和仅已下载的模型，重新打开后仍由实际记录推导。无显式目标的安装／修复保留可识别的实际组合，无法匹配的自定义组合必须明确选择目标，避免意外换模型。档位下方以共用 FlowNode 的两张并列卡展示所需 ASR/TTS；reload 时检查当前 pin 的文件、revision stamp 和大小，缓存是否就绪，不只依据安装记录，也不做全量 hash。

Apple Speech 是独立识别偏好，LISTEN 与 SPEAK 分别保存，默认 Qwen；选 Apple 不触发安装器或改变 TTS。SPEAK 跳过可选 Qwen 主识别并保留现有 AppleFinalizeASR 的暂停预览流程。旧 compact16 安装仍强制两路 Apple，不改写保存偏好，离开该安装后恢复选择。模型删除入口在空闲时允许删除当前角色，原生确认说明影响；会话启动、活动、停止及试听期间阻止当前角色删除。UI 使用显式 removeActiveModel 操作，安装器先停止引擎再传 --allow-active-model；CLI 默认拒绝删除 active role。删除仅移除目标及该角色，不自动启用额外模型；重新下载也不自动激活。具体 revision、文件散列、依赖与配置以 `scripts/lib/versions.sh` 和 lock 文件为准。
同场 LISTEN/SPEAK 复用一个 OpenAI 后端及其熔断和连接状态，各方向保留独立开关；语言热切换不能新建后端割裂这些状态。模型设置在下一场生效，术语表按请求读取，最多 30 条生效。
云端只接收待翻译文本、短上下文和术语；未同意或关闭时走 Apple。超时、网络及服务错误按既有预算兜底；翻译结果仍须经过目标文本与数字检查。
SPEAK 的文本／数字检查触发云翻译重试时，在既有 `startAppleAtHedge` 开关开启且非 `appleLate` 退化状态下，同步准备原请求的 Apple 备用结果。沿用同一个可取消的 AppleAttempt，正常轮已启动时不重复计算；云端优先级、截止时间、数字重试首译保留及文本／数字／术语检查不变。提前准备不意味着提前采用备用。此延迟优化不修改 Qwen 或 Ming 的模型、采样种子、生成参数、声音参考、校准及播放参数。

三个场景启动时，翻译模型目录不再作为串行前置网络请求：先用本账号已缓存目录处理模型退役，再后台刷新并按五分钟冷却去重；设置中的显式刷新仍重新请求，换 key／删除 key／撤销同意会使旧响应失效。后台目录更新不修改已建立的会话翻译后端。权限探针保持每次核验，读到第一段非零音频即判定已授权并结束 afplay，全零或未确定时仍等完整播放；之后 ASR 打开和 Apple Translation 准备并行，二者完成才报告收听就绪。会议和电话在探针之前（电话在打开 Phone 之前）按原加载顺序启动引擎，使模型加载与探针重叠；此时不进入会议模式，`.started` 后由 SPEAK 接管，之前的任何退出都交回正常的空闲退出。结束会话或替换识别器时调用 ASRStream.cancel，丢弃已不再消费的结果并等待同一关闭任务释放识别器；需要最终文本的 clip 路径继续使用 close/finalize。阶段日志只记请求时间、探针／启动／停止耗时和采集停止事件，不增加音频或文字保存。

引擎挂死检查只统计未取消、未完成的工作；last_step_age_ms 从当前可运行工作的起点或最近 GPU 步进开始计时。播放缓冲上限、SPEAK 暂停 LISTEN 和共享解码器等待不算卡死；恢复工作重新计时，新到任务不能重置已有停滞任务的计时。四秒保护阈值、长步骤豁免和会后十分钟保温规则保留。
有可用声音档案时使用“我的声音”，否则按当前策略使用系统声音或停止发声；界面必须说明实际选择与不可用原因。
同一次发言由第一段合成锁定声音，克隆临时不可用时默认等待或停止发声，不能静默改用系统声音。已有档案读取失败时保持待恢复，不能当成“没有档案”；恢复试听后仍尝试卸载临时声音。实际首声播放记录 clone/system、语言和任务编号等元数据，不记录正文、录音或声音档案标识。所有共享 TTS 解码器的生成任务（含通用预热和声音预热）在生成器结束或关闭前独占该解码器；达到播放缓冲上限时仍保持所有权，ASR 可继续穿插，不能让预热重置正在合成语音的解码状态。

正式发言与试听的合成请求携带预期 conditioning key。加载时核对请求中的模型、档案 key 与 blob，等待就绪时核对 health 中的 key 摘要；引擎在同一锁内验证当前档案已就绪并捕获其对象/代际，排队任务开始前再次检查。错配、未就绪或被替换时拒绝合成，不能借用当前槽中的其他声音。档案句柄必须来自实际加载的有效 conditioning blob。API v2 的低层离线调用保留可选字段兼容，但正式产品调用必须绑定身份。该校验只证明使用了预期参考，不能证明模型生成的音色与本人一致；`clone` 路由标记与试听相似度均不能充当逐句音色质量证明。

不同 TTS 的 conditioning 与试听音量校准按模型及完整缓存 key 隔离。切换时保留非活动模型的缓存与校准；切回可复用仍有效的原模型结果，版本或参考变化则重新准备。真人 reference.wav 和 script.txt 不随模型切换改写，重录／删除仍作用于整个声音档案。旧档案缺少新增缓存字段时兼容读取。

Qwen TTS 重复惩罚在 1.0.10 按用户要求恢复原有 1.5 下限。此前 1.0.8 的三组英/德本地 A/B 中用户偏好模型默认 1.05，但之后实际使用和重录效果不理想，故回退该参数；不将任一参数当作音色稳定性保证。保留最近 64 token 惩罚窗口、固定种子、流式预留及现有 runaway/short/echo 保护，不引入整句 F0 筛选后重生成的额外等待。已有参考补尾与 conditioning 不变。

从 1.0.12 起，正常合成、告知语与声音试听统一按声音档案和输出语言固定初始采样种子，不再随每段文字改变。FNV 的 profile/key/mode 前缀保留，英/德各使用冻结的 v1 常量盐，精确保留本轮 C 组听验的数值；盐只是哈希输入，不传给模型、不经过本地化。异常重试仍使用原有 successor seed，且仅在音频尚未释放前重试。1.0.13 增加可选 `sampling_key`：编辑同一声音参考并要保留已听验采样时，用该原身份计算 seed；实际加载、请求校验始终用新 conditioning key。旧档案无该字段时行为不变。保存声音的试听、重建与正式发言一致使用这一采样身份；配套文本从保存的 `script.txt` 读取并核对其哈希。

1.0.13 的句间声音衔接仅在同一录音轮次内启用。克隆请求按生成完成顺序提交，带会话随机 ID/epoch/press/语言组成的临时作用域和显式前驱 job。引擎核对作用域、前驱、声音 key/代际及语言，只把最近一个完整成功、首次生成的前句文本与 codec 作为额外 ICL 条件；真人原参考和 speaker embedding 不变。下一句仍重新建 KV、reset decoder，再用组合参考尾部预热，不把旧生成器跨任务偷接。最多保留一段不超过 8 秒/100 帧、512 字符的前句，不累计合成历史，不写声音档案或磁盘。失败、重试、短段、跑飞、echo、超限不进入缓存；取消、换档案、引擎退出使其失效。新录音轮次和不同语言不会沿用旧句；告知语、试听默认不参与。缺少合格前驱时按真人参考正常生成，不增加等整段发言结束的缓冲。

完成元数据记录 `attempts`、`echo_aborts`、`context_used`，不记录正文、声音 key、seed 或临时作用域标识。句间衔接基于本人的两句英语对照选择，不能以生成成功或该样例外推所有长发言、第一句音色或德语效果。

声音录入使用 `zh-v2` 的 71 字中文稿，引导自然朗读约 10–20 秒；有效时长检查沿用压缩长停顿的计时方式，范围改为 10–20 秒，原始录音上限为 25 秒，读完后 1.2 秒静音自动结束。新稿只用于新录音；既有档案继续使用其保存的文本和 conditioning，不因升级而失效或自动重建。重录过程中试听生成失败不得自动覆盖旧档案，恢复原有声音；成功试听后由用户保存替换。该时长是产品选择，不是官方最佳时长或音色稳定性保证。

翻译轮次隔离：ASR 的上一句原文提示只用于同一轮的非收尾片段，术语表可跨轮；不能把上一轮原文继续作为下一轮识别提示。1.0.14 起，最终/结束尾段只带术语，不带上一句整段原文，降低短尾被上下文诱导成旧句的风险；不按文字相同直接删除，真实重复发言仍须保留。无正文诊断补记相邻采集区间重叠毫秒，以及识别结果字数、是否与同轮上一条接受原文精确相同；这些是定位标记，不代替音频验真。上一轮已结束、仍在 250 ms 收尾时，快速再次开启按新按键边界交接待收尾音频，旧回调不能清除新轮的占用。新轮空字幕快照即使先于音频模式更新到达，也必须清除旧字幕；原声模式的非空识别草稿仍被拒绝。上一轮尚未播完的译音按原规则继续排空，不因新轮开始而重播已消费样本或丢弃未播内容。

`firstSampleEnqueued` 只界定重试边界；已说历史、播放状态和首声指标以 `firstSamplePlayed` 为准。GPU RTF 使用计算时间，不把 HTTP 等待算作 GPU 工作。
告知语在内存中准备，与用户处理并行；失败或超时不能无限阻塞用户句。未验证的码本缩减和自动热备不启用。

## 数据与隐私

- API key 存于 macOS Keychain，不进入命令行、日志、诊断包或引擎；正常音频处理不上传录音或声音档案。
- 常规事件日志默认不含原文和译文。转写、诊断录音和字幕分析分别显式开启，不能以诊断为由默认录制全部会话。
- “本次字幕分析”含原译文和阶段时间，不含音频；不持久化开启偏好，会话结束自动停止。目录 0700、文件 0600，上限 8 MiB / 10,000 行，达到上限在 UI 显示停止。
- 字幕显示时间是 AppKit 提交更新时刻，不是光学显示时刻；缺 voice-end 或参考转写时，不计算伪 EVS、准确率或主观质量分数。
- 诊断导出使用白名单，私有记录按留存策略清理；声音资料与分析文本不进入仓库。合成测试音频同样不提交。

## 构建与验证边界

`build-app.sh release|dev` 在共享打包锁内先检查生成 pins，再预留递增的 `TT_APP_BUILD` 并生成对应 Swift 常量；编号高于同发布版本的源码、本机已打包与已安装包，失败的编号不回收。完整打包期间保持锁，避免开发包与正式包混用编号或驱动产物。`TT_APP_VERSION` 继续显式维护；普通 `swift build/test` 不递增构建号。编译后二进制 `--version`、包内 Info.plist、设置与菜单使用同一份版本／构建信息，并在打包 smoke 中校验。

版本和组件 pins 从 `scripts/lib/versions.sh` 生成；更改后运行 `scripts/gen-pins.sh`，不手改生成文件。安装器验证 revision、大小与 SHA-256，最后写入安装记录。
