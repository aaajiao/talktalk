# TalkTalk 架构

本文是当前设计依据。改变模块边界、音频路径或隐私约束时，先在这里记录理由并同步实现。
功能与验收状态见 [remaining-work.md](remaining-work.md)；构建和使用入口见 [README](../README.md)。

## 平台与模块

TalkTalk 是面向 Apple Silicon 的菜单栏应用，部署目标为 macOS 26；Apple 本地翻译要求 macOS 26.4 及以上并安装对应语言资源，因此使用说明采用 26.4+ 作为完整功能要求。SwiftPM 使用 Swift 6.2 工具链、Swift 6 语言模式；界面采用 AppKit 与 SwiftUI，应用本身不链接 MLX。

| 模块 | 职责 |
|---|---|
| `TalkTalkApp` | 应用装配、菜单、设置、引导、字幕与发言 HUD |
| `TalkTalkCore` | 协议、策略、时间、文本检查、状态机与配置 |
| `TalkTalkSession` | LISTEN/SPEAK 流水线、会议生命周期、按键与原声门控 |
| `TalkTalkAudio` / `CAudioCore` | HAL 采集与输出、重采样、环形缓冲、实时 C 回调 |
| `TalkTalkApple` | Apple Speech、Translation、系统声音适配 |
| `TalkTalkCloud` / `TalkTalkCloudUI` | OpenAI 文本翻译、熔断、连接保温、云端设置 |
| `TalkTalkEngineHost` / `engine/` | 私有 Python 进程、安装器、MLX ASR/TTS、流式协议 |
| `TalkTalkVoice` | 声音录入、校准、校验、存储与试听 |
| `TalkTalkDriverSupport` / `Driver/` | 虚拟麦驱动、安装卸载、状态检查与隔离自检 |

`TalkTalkSession` 通过 Core 协议接收云端和本地引擎，不直接依赖 Cloud、EngineHost 或 Voice。App 层负责把具体实现装配起来。

## 三种使用场景

- **会议同传**：听英语或德语，显示原文与中文；自己说中文（可夹英语），翻译为英语或德语并送入会议。
- **电话同传**：独立使用场景、菜单入口和字幕外观，通过系统 Phone 与 iPhone 使用本人的号码；先准备同传，再在 Phone 拨号/接听，或将界面填写的号码交给 Phone。挂断由 Phone 操作，结束同传由 TalkTalk 操作并恢复输入。
- **视频字幕**：只收听所选应用并显示双语字幕，不开启麦克风、SPEAK 或默认输入切换。
- 场景决定工作方式，来源属于场景。会议页选择“会议应用”，视频页选择“视频声音来源”，分别保存选择；同一个浏览器可以用于两种场景，但互不覆盖偏好。Phone 仅属于电话场景。自动选择分别依据麦克风活动或播放活动；明确选中的应用不可用时提示未就绪，不静默换源。运行中的来源只读，结束后再更换。浏览器来源包含该浏览器的其他标签页，不保证只捕获一个标签页；全局采集仅作当前非电话会话显式选择的备用方式。
- Mac 的 Phone（`com.apple.mobilephone`）作为独立来源复用会议同传，与 FaceTime 分开显示。来源归属先采用同 PID 的已知运行应用身份，再回退到 Core Audio 的 bundle ID、父进程与 responsible PID；不因 Phone 正在运行就把共享通话服务或真正的 FaceTime 归给它。Phone 的“音频 › 麦克风”可选“使用系统设置”，复用现有 TalkTalk Mic 默认输入管理；应用识别与真实电话双向音频验收分别记录。
- 使用场景与字幕页采用图标卡片标签（模型、组件、隐私与诊断的子页用原生分段控件，选中页摘要显示在其下），选页本身不启动或切换运行会话。菜单入口打开各自场景页，移除跨场景的全局来源选择；会中菜单只显示当前来源。电话模式固定绑定 Phone，不沿用或覆盖会议/视频的来源，不允许全局声音备用。准备时先打开 Phone，再建立 LISTEN/SPEAK 与 Feed；无需等电话接通即可显示“电话同传已就绪”，拨号按钮只在真实语音链路和输入路径准备完成后可用。电话号码仅为内存草稿，校验后显式交给系统 Phone 的 `tel:` 入口，不保存或写入日志，不自行接听或挂断。
- 电话模式准备完成即开启本机实体麦采集，并可点按右 Option 开始翻译，不等待 Phone 的通话读者。Feed、系统输入、实体麦和按键状态必须真实可用；明确没有远端读者时采用独立的本地发言就绪判断，不把守卫伪装成已确认，也不修改原声门的读者与输出检查。首次确定的读者状态仅建立基线；之后真实读者出现或消失时，先关闭当前发言并串行取消旧识别、翻译、合成及待播译音，再恢复流水线，最后解除本地发言屏障，避免恢复期间提前显示就绪。清理是短暂屏障，不持续等待读者；递增令牌与会话/流水线身份在清理前、恢复前及完成后隔离过期任务，防止旧事件暂停新流水线或提前解除新屏障。该事件可能是静音、保持、设备切换或通话边界，不用讲话静默或音量推断。用户结束同传或准备失败会拆除会话并恢复输入；长时间无应用音频仍按既有 10 分钟提醒、60 秒后结束规则处理。
- 使用场景页的主操作栏固定在滚动内容之外，显示当前场景的开始、准备或结束操作；已有会话时，即使浏览其他场景，主操作仍结束正在运行的会话。所有设置入口共用 `show` 的前台激活路径，恢复被隐藏或最小化的窗口，并在菜单跟踪结束后按本次请求补做一次前置；窗口保持普通层级，不长期悬浮在其他应用上方。
- 菜单栏空闲时第一项为粗体 `play.fill` 快速开始：按上次场景与来源写“开始会议同传 · Zoom”，来源为自动时写“· 自动选择”，电话写“准备电话同传”。其下是它的原生灰色副标题（`NSMenuItem.subtitle`）“上次：会议同传 · 英语 → 中文”。`ui.lastScenario` 在会话开始时写入。快速开始直接开始，不打开设置；需要选来源时打开对应场景页，不弹选择对话框。失败时先显示既有“未就绪”提示，明确选中的来源不可用时不静默换源。原有三个“…”入口保留。会中菜单顶部为粗体“场景 · 来源 · 计时”，菜单打开期间每秒更新；其下是同色发声图标（胶囊自己的符号，风险态为带角标的 `mic.fill`）加“发声：…”一行，然后是“显示字幕”“恢复字幕窗口”、视频专属的“锁定字幕位置（鼠标穿透）”和“结束<场景>”。菜单的“结束<场景>”与标题栏结束按钮问同一句确认（会议、电话为警告框：破坏性“结束同传”不响应回车，“取消”对应 Esc；视频直接结束）。菜单栏图标：待机 `captions.bubble`，组件缺失时同一图标变暗；会中 `captions.bubble.fill`；准备 `hourglass`；说话 `waveform`；原声 `mic.fill`；音频未确认橙色 `questionmark.bubble`；备用方案橙色 `exclamationmark.triangle`；需修复红色 `exclamationmark.bubble`；会议应用读实体麦（对方能听到原声）时为红色风险图标（`mic.fill` 加 `exclamationmark.circle.fill` 角标），优先于原声图标，tooltip 为“TalkTalk · 对方能听到原声”。
- 使用场景页的 `requestedScenario` 持久化到 `ui.requestedScenario`，切换场景时滚回顶部。内容上滚超过 24pt 时，三张卡片收成 32pt 分段控件，回到 4pt 内展开。运行中的卡片有 8pt 绿点和“运行中 · 12:03”，与选中描边独立。底栏左侧固定显示“正在运行：<场景> · <来源>”，前面的圆点与菜单一致取当前发声状态的颜色（原声绿、译音蓝、警示橙、风险红，视频收听为中性），停止按钮为红色；浏览非运行场景时，顶部固定提示“…正在运行，结束后才能开始…”并提供“回到…”。字幕已隐藏时，底栏显示橙色“字幕已隐藏 [显示]”。会话开始时，字幕设置标签同步一次。每个场景只留一句不超过 24 字的摘要，操作提示收进 ⓘ 弹层；浏览器标签页说明只在所选来源是浏览器时显示。
- “我说话”分两条泳道：上为“默认 · 原声”，下为“点按 右⌥ · 翻译”，中间为回环说明。胶囊与键帽复用字幕窗口的组件，在浅色设置界面使用浅色取值。流程节点统一为一种卡片（圆角 10、quaternary 填充、最小高 44），“模型设置 ›”等链接位于卡片下沿。从场景页跳到其他设置页后，目标页顶部显示可关闭的“‹ 返回 <场景>”胶囊，返回时恢复原滚动位置。电话页为三步清单：① 准备（完成后“已就绪，可拨号”），② 拨号或接听（① 完成前 50% 并禁用），③ 挂断后结束同传，用纯文字说明。
- 字幕设置页的场景卡片跟随 `requestedScenario`；点卡片只切换预览，不启动或切换会话。预览把真实标题栏、时间线、状态带和视频字幕视图按实时窗口的逻辑尺寸渲染：会议／电话 760×480（含标题栏），视频 960×150 悬停态。这样断点、标题栏退让与字号公式都与实时窗口一致，再整体缩放到设置栏宽度。预览玻璃是真实 hudWindow，用 within-window 混合模糊下方可切换的“浅色网页／深色视频帧”背景；所选背景按场景暂存，不保存。预览外框圆角 12、带阴影，不再套外层卡片。它不接收点击，是单一 VoiceOver 图像，也不启动音频、会话或计时器。页面新增“朗读新译文（VoiceOver）”，视频另有“字幕样式”“排列”“长静默时变暗”。描边样式下不透明度滑块置灰并说明“描边样式不使用背景”；减少透明度时，视频说明改用实底。
- 首次引导先问“你会用 TalkTalk 做什么？”，三张卡片可多选，选择保存在 `onboarding.v2.scenarios`。只选视频时，路径为仅收听权限、语音资源、试一次，标题“准备视频字幕”。只选电话时标题为“准备电话同传”。步数按所走路径编号；第 1 步点“上一步”回到选择页。点“完成”后进入完成页：主按钮“打开使用场景”打开设置并定位到所选的第一个场景；“关闭”为次要操作；三个场景也可直接点开。

## LISTEN：对方音频到双语字幕

```text
所选应用 → Core Audio process tap → AudioIngest / TimeMap
        → Qwen ASR（默认）或 Apple Speech → 句子定稿
        → Apple 草稿 / OpenAI 定稿（不可用时 Apple 兜底）
        → 数字检查 → SubtitleBoard → SubtitlePanel
```

Qwen 在共享引擎中以较低优先级运行，冷启动先等待 ASR 就绪；不可用或识别失败时接管到 Apple，界面显示实际引擎状态。
原文语言与 ASR 选择可在会话中切换；配置代际隔离旧回调，切换清空旧字幕和待显队列，不重启 SPEAK 或默认输入管理。
LISTEN 的数字检查结果仅保留为元数据供已有诊断使用，不再向字幕正文附加“数字待核”等提示文字；不改变翻译结果或数字校验行为。
最终字幕按句配对保留原文和译文。会议和电话保留独立草稿，由 `ConversationTimeline` 把远端句对与自己的按键发言按到达时间合并成一条时间线；保存最近约 60 秒的阅读窗口，最多 24 段、原译文合计约 6,000 字符，只按已定稿行计算，按完整句对退出，始终保留最新一对，已淘汰的句对不再回来。识别代际保证正在识别的远端原文不与另一句的草稿配对。字幕重置（换原文语言或配置）只清远端句对、保留自己的发言；会话结束或换场景全部清空。时间线只在内存中，不写日志。视频使用独立单句呈现：当前原文与中文占用两个固定区域，草稿携带真正提交翻译的原文，定稿在同句同位置替换，不能叠加成第三段；后续句对最多待显两组，按阅读节奏整体前进，积压淘汰较旧待显句，迟到结果不倒退画面。原始 ASR 文字仅在尚无句对时作为原文单独显示，不能与另一句译文配对。短暂停顿不自行清空；视频另有长静默变暗：最后一页阅读时间过后 8 秒既无待显句也无原文变化时，文字降到 35%、玻璃或行块降到 min(原值, 40%)，300 ms 过渡；新定稿、草稿或非空原文变化，以及清空、显示、恢复窗口时立即还原。只有占位提示时不变暗。偏好 `ui.videoLongSilenceDim`，默认开。显示窗口不限制识别、翻译或音频工作，也不作为传给模型的历史。支持字号、拖动与位置保存，不抢键盘焦点并从屏幕共享中排除。

视频长句依据 AppKit 的实际字体与逐字宽度分页（`VideoCaptionPager`），固定原文区与中文区不使用记录式滚动或自动跟尾。原文块和中文块每页都最多 2 行，原文只在高度允许时用 2 行。断点向前回找不超过半行，优先落在“，。；？！、”或 `, ; . ?` 之后。两行页取最均衡的断点，标点断点与最均衡点相差不超过 15% 行宽时优先标点。第二行不得只剩 1–2 字或单个标点，过小的末页会回拉断点；行首不放闭合标点，拉丁单词不拆开，除非一个词就超过整行。原译文分别保存阅读位置，较短一侧保持最后一页，较长一侧继续，异步增长不能跳过中间内容。草稿与定稿同字号：草稿中与上一版相同的前缀为白 100%，变化的尾部为白 65% 并在句末加“…”，定稿 150 ms 过渡到 100%。相同或仅追加的定稿保留阅读位置，早期文字或数字修正则在定稿后回到对应修改位置，草稿期间已发生但尚未展示的修正也要保留。每页按原文每秒约 18 字符、中文每秒约 9 字符估算，取较长者并限于 1–6 秒，重复停留的一侧不再次计时；翻完当前句才切换下一句。有待显句时当前句每页时长 ×0.7（下限 1 秒），先追赶，追不上才淘汰较旧待显句；淘汰时在原文位置显示 1.5 秒“已跳过 N 句”（12pt，白 50%，增强对比度 75%）；“朗读新译文”开启时以 low 优先级向 VoiceOver 播报。最旧待显句等待超过 5 秒时，作为外部问题“字幕落后约 N 秒”（`clock.badge.exclamationmark`）进入问题槽，右上角显示黄色警示符号。隐藏／最小化时暂停翻页，恢复时重新给予当前页阅读时间。字幕分析区分完整句身份与实际可见页，报告中的已显示不代表整句所有页面均已阅读。

视频排版：中文块宽 min(20×中文字号, W−48)，原文块宽 min(46×0.52×原文字号, W−48)；窄窗（< 640）时宽 = W−48。两块水平居中、间距 6pt，整体底部锚定：下方文本块末行基线距内容底边 12pt（由 TextKit 量出），单行时整体下沉；窗口加宽只增加两侧留白。默认原文在上，可选“中文在上”（`ui.videoCaptionArrangement`）。还有下一页时中文末尾加白 45% 的“›”，中文块下 4pt 画页点（3pt，间距 4，当前页白 90%、其余 30%），最后一页不显示。翻页先淡出 60 ms，留一帧空白，再淡入 60 ms。空状态在原文位置显示“正在听 <来源>…”（14pt，白 60%）。两个文本区的 AX 标签为“原文 · <语言>”“译文 · 中文”。字幕样式按 `ui.videoCaptionStyle` 保存，三选一。贴合玻璃（默认）：窗口本身透明，只在两个文本块的外接框铺一块 hudWindow 玻璃（内边距 16/10，圆角 10，alpha 为场景不透明度），不透明度 < 0.75 时叠加描边阴影。描边：无底板，阴影黑 85%、模糊 3.5、偏移 (0,−1)，加 −3 黑色描边并保留填充，不使用背景不透明度。实底：每行文字后垫圆角 6、黑 0.62 的行块，左右各 0.4em；系统“减少透明度”开启时强制使用实底，不透明度 0.85。窗口最小高度由字体度量保证 2 行中文 + 1 行原文 + 24，默认内容 960×150，首次位置在 `visibleFrame` 底边以上 8% 高度处水平居中；内容更新不改变窗口尺寸。

视频窗口使用透明标题栏和 `fullSizeContentView`，隐藏绿色缩放按钮，平时不显示标题栏。指针进入窗口（`.activeAlways` 追踪区）时，原生标题栏与 28pt hudWindow 条在 200 ms 内淡入，显示红黄按钮、`play.rectangle` 加来源名（“视频字幕 · 来源”在 tooltip、AX 与窗口标题中）、只读 12pt `ear` 收听图标（不画胶囊）、问题芯片、`⋯` 菜单（VoiceOver 角色为菜单按钮）和“结束”；离开 1.5 秒后用 200 ms 淡出，减少动态效果时直接切换。完全淡出后隐藏，不接收点击。VoiceOver 运行时（KVO 观察 `NSWorkspace.isVoiceOverEnabled`）悬停条常显。本窗口打开的浮层或 `⋯` 菜单会保持已显示的条，但不会让隐藏的条重新出现。黄／红问题时右上角常显 10pt 警示符号（白叹号；warn 黄 `exclamationmark.triangle.fill`，risk 红 `exclamationmark.octagon.fill`；带阅读阴影）：符号画在内容中、不参与命中测试，点击区是标题栏附件尾部预留的 26pt 内不可见控件，携带 AX 标签与说明，点击打开详情浮层；悬停条隐藏时符号本身是 VoiceOver 按钮。`⋯` 菜单与会中菜单栏菜单都有“锁定字幕位置（鼠标穿透）”（`ui.videoSubtitleLocked`，仅视频生效）。锁定后窗口 `ignoresMouseEvents`、不可移动，悬停条不再出现，右上角显示 10pt 白 40%（增强对比度 80%）带阅读阴影的 `lock.fill`，VoiceOver help 说明从菜单栏解锁；只能从菜单栏解锁。未锁定时只有文字块（玻璃框，或描边／实底时文字外扩 16/10）与悬停条能拖动窗口；透明区域接收点击但不拖动、不动作，不会穿透到下层应用。首次出现在全屏 Space 时，窗口内提示一次“可拖到画面外，或在菜单中锁定”（向 VoiceOver 播报一次，增强对比度时加 1pt 描边），6 秒后 300 ms 淡出，记入 `ui.videoFullScreenHintShown`。全屏 Space 没有公开 API，只按其他应用占满整块显示器的 0 层窗口推断，仅读取边界、层级与进程号，不保存、不记录。

会议内容只使用一个浮窗：对方/视频双语字幕与自己的按键翻译反馈在同一窗口显示，共享标题栏、拖动与位置记忆。窗口可拖动边缘调整尺寸，高度用来增加可见行数；保留用户设定的尺寸，内容和状态变化（包括状态带伸缩）只移动窗口内部的分隔，不改变窗口外框。会议/电话的对方译文字号 F = B×clamp(√(W/760), 0.85, 1.30)，再夹到 [14, 1.3B]，原文 max(12, 0.78F)，我的译文 0.86F。视频中文为基础字号 B，只在 640–1200pt 宽度间 ±15% 微调，窄窗下限 min(18, B)；视频原文 max(14, 0.66B)。B 默认会议/电话 22、视频 26。颜色、字号、间距、圆角与动效统一取自 `SubtitleTokens`。背景采用 macOS 原生半透明材质，可调背景不透明度。不透明度 < 0.75 时正文加阅读阴影；“增强对比度”开启时不透明度至少 0.95，并使用高对比颜色与 4pt 色轨。系统“减少透明度”优先：会议、电话改为不透明，视频改用实底行块。三项辅助功能显示设置一起读取，“减少动态效果”时所有过渡直接切换。原声直通只发送声音，不启动自己的按键识别；收听链路应过滤已确认的本机原声回流，不能在默认原声门打开的整场期间停掉对方字幕。

窗口呈现按场景明确区分。会议同传自上而下为标题栏、列头、一条句对时间线和底部麦克风状态带。列头整窗只出现一次：“原文 · <识别语言>”“译文 · 中文”，电话为“通话对方 · <语言>”；它只描述远端语言，不描述自己的行。句对行由三部分组成：24pt 说话人轨、原文 40%、间距 16、译文 60%。行高取两列较大者，顶端对齐，行间 0.5pt 分隔。轨区竖条 3pt（增强对比度 4pt）：对方为 speaker.remote，我为 voice.translate；同一说话人的连续行相连，一段的首行放 16pt 标记（对方 `person.wave.2.fill`，电话 `phone.fill`，我 `person.crop.circle.fill`；`mic.fill` 在此界面只表示原声）。我的行有 meRow 底色并在译文末尾显示送达标签，悬停整行加亮。原文高度超过译文 2 倍时截断，末尾为“…”加 `chevron.down.circle`（tooltip 与 AX 为“展开原文”），点击就地展开。正文三态：正在识别的原文为 sourceLive，句末带不闪烁的静态竖条光标；译文草稿与定稿同字号、同字重，用 draft 色，末尾“…”，左缘有 2pt 竖条；定稿时竖条消失，150 ms 过渡，不回流。Apple 备用翻译不再用“≈”前缀，改为句末 10pt“备用翻译”胶囊，tooltip 与 AX 为“云端不可用，本句由 Apple 翻译”。未提交短尾显示为 warn“未发送”标记加未发送文字。送达标签依据实际播放结果：会议为“已送出”（`checkmark.circle.fill`）／“未发送”；电话为“已送入 Phone”（仅 Phone 读者已确认）、“仅本机 · Phone 未接收”或读者断开时的“已中止”。处于风险或不可用时的播放不算送出。行内标记都有 tooltip，tooltip 与 VoiceOver 文本以可见字开头再加说明，不声称对方已听到。断点：内容宽 < 520 时句对上下堆叠（译文在上）；内容高 < 260 时状态带收成 28pt 单行（图标、短标签、迷你曲线，无键帽；修复／详情只留 20×20 图标；隐藏的后果说明在 tooltip 中）；内容高 < 140 时只保留时间线最后一行，状态带不展开，自己的实时发言作为最后一行显示。最小内容高度由字号决定（F=22 时约 101pt）。空状态：会议居中显示“正在听 <来源> 的会议声音…”；`meetingSilent` 时显示可点击的“暂未听到对方声音”，前置与标题栏芯片和菜单提示行相同的 `waveform.slash`（收听中为 `ear`，电话为 `phone`），tooltip“查看详情”，点击打开详情。电话显示“接通后在这里显示对方的字幕”及 Phone 拨号、挂断说明。第一条字幕到达后，占位提示 120 ms 淡出。每个句对行是一个 VoiceOver 元素。“朗读新译文（VoiceOver）”（`ui.announceNewTranslations`）默认关；开启且窗口可见时，每条远端译文定稿和视频中文定稿以 medium 优先级播报，草稿和自己的译文不播报。只有变化的行会重建，通常是最后一行。

麦克风状态带空闲高 48pt，上缘 0.5pt 分隔。左侧为状态图标、13pt semibold 状态文字（发声状态色）和 12pt 后果说明；中间是开始提示与弹性 24pt 曲线带；右侧为键帽，只显示键，不带动作文字。状态文字随发声状态变化：原声为“原声 · 对方能听到你”，翻译收音为“翻译中 · 原声已关”，按下未松开为“松开 右⌥ 确认”。译音尚未实际播放时为“译音处理中 · 原声已关”，Feed 实际播放时才显示“译音播放中”；恢复中显示“正在恢复原声…”，未发送为“未发送 · 对方听不到你”。原声风险使用红 18% 底、左缘 3pt 红条和“修复…”（`wrench.and.screwdriver` 加文字）；音频不可用使用 warn 15% 底和只有 `info.circle` 的“详情”按钮（tooltip 与 AX 为“详情”）。增强对比度时曲线为状态色 85%、线宽加 0.5pt。这两个按钮与键帽都打开详情浮层。电话按 Phone 读者分态：已确认的原声写“原声 · 正在送入 Phone”，不声称通话对方已听到；未确认时为“本机试说 · Phone 未接收”或“译音只在本机播放”。读者断开期间显示“当前发言已停止 · 等待 Phone”。发言态从翻译锁存开始，到待处理工作结束后再过 3 秒，状态带在 180 ms easeInOut 内展开到 min(内容高 34%, 160pt)。展开时底色为蓝 10%、左缘 3pt 蓝条，按时间线的列显示我的实时原文与译文草稿。收回时本轮作为“我的行”插入时间线；最终结果未到的非原声轮次以草稿样式保留。状态和电平更新不重建正文。电话同传复用时间线、状态带和标题栏；没有 Phone 输入读者时，也必须在实体麦实际开启且本地链路可用后才显示“电话同传已就绪”。本地就绪不表示电话已接通或对方正在接收声音。三个场景独立记住尺寸、位置、基础字号和背景不透明度；旧的共有偏好仅继承给会议场景，显示字幕总开关仍共用。场景仅由会话/引导入口决定，切换设置标签或收到迟到的音频状态不得切换窗口场景。

时间线默认跟随底部。手动上翻后整条时间线一起冻结，只额外保留一份最新显示快照，并统计冻结后新增的定稿数。N > 0 时，在时间线底部、状态带上方 8pt 处居中显示 `arrow.down` 加“N 条新字幕”的胶囊（tooltip“回到最新字幕”）；点击或滚回底部恢复跟随。冻结不暂停上游处理、不累计无限历史；新一轮自己的翻译发言或会话重置立即解除冻结并替换快照。字幕分析只记录实际显示的行，冻结期间不记。视频保持字幕的即时更新行为。

会议和电话的标题栏请求 32pt 高度，右侧固定顺序为 `[发声胶囊 ⌄] [问题/通知芯片] [右⌥ 键帽 + 动作] [Phone ↗] │ [结束]`，隐藏的控件不占位。AppKit 可能保留原生标题栏高度，控件按实际高度居中。左侧依次是原生红黄按钮、统一场景图标（非无障碍元素）、13pt semibold 场景名和 13pt 白 60% 的“ · 来源”。原生标题隐藏，但保留给辅助功能。标题栏控件接受首次点击、不拖动窗口、指针为箭头；标签预留 4pt 尾部空间，避免短词被截成“…”。键帽动作“开始翻译”“结束”在任何宽度都显示为键帽后的图标（`translate`／`stop.fill`，VoiceOver 与 tooltip 仍读文字）；“松开确认”“本机试说”保留文字，窗口宽 < 560 时只留键帽。翻译中键帽为蓝色实底。电话的“Phone ↗”（`arrow.up.forward.app`）是唯一的 Phone 入口，状态中不再出现 phone 图标；`phone.arrow.up.right` 只表示“已送入 Phone”。窄窗按 `TitlebarCompaction` 依次退让：来源名截断、键帽动作文字、Phone 文字、结束文字（改为 `stop.circle`）、芯片文字，最后胶囊缩成两字（原声／译音／本机；视频为收听），风险态最短为“对方听到原声”。胶囊永不隐藏。“结束”默认白 70%，悬停变红；AX 标签与 tooltip 按场景写“结束会议同传／结束电话同传／结束视频字幕”，help 说明会议或通话本身不会结束；视频的 tooltip 与 help 为“结束视频字幕：停止收听和翻译”。会议与电话写“结束同传”，点击后从按钮弹出 260 宽的确认浮层，不要求浮窗成为 key；“结束同传”按钮为 systemRed。电话正文为“通话不会挂断；结束后对方将听不到你的声音。”。会议正文按 TalkTalk 当时是否接管了系统默认输入选择：接管时为“系统麦克风还原后，会议仍会收到你的原声”，否则为“结束后会议将听不到你的声音”。会议应用是否跟随默认输入无法观察，这只是近似判断。视频与引导演示直接结束，电话仍由 Phone 挂断。场景图标三处统一：会议 `person.2.wave.2`、电话 `phone`、视频 `play.rectangle`。`mic.slash` 只用于原声已关和不可用；原声风险用 `mic.fill` 叠加 `exclamationmark.circle.fill`（0.72×，周围清出 1.5pt 空隙），因为当前 SDK 没有 `mic.badge.exclamationmark`。`speaker.slash` 只表示什么都没发出去（未发送、未接入 Phone）；声音只在本机（本机试说、仅本机、本机播放、“Phone 未接收”）用 `laptopcomputer`；重新连接与音频重启用 `arrow.triangle.2.circlepath`；“已中止”用 `xmark.octagon`，`stop.circle` 只给用户的结束操作。标题栏描边、虚线、分隔线与次要文字使用带增强对比度取值的 control 令牌；自绘控件有按下态，并向 VoiceOver 报告停用状态。视频警示符号始终以三角（warn）或八边形（risk）区分。视频标题栏为悬停显示，见上文。底部不再预留状态或操作行；关闭全部正文时只保留标题栏，不覆盖已保存的阅读尺寸。场景切换会重置旧文字与冻结状态，字号变化保持阅读位置。

HUDModel 输出两个独立属性：`voiceState` 由当前发声模式直接得出，不参与问题竞选；`issueSlot` 按问题 > 通知 > 信息 > 云端说明排序。两者在标题栏并列显示，互不覆盖。只有 `remoteHearsYourVoice`、`meetingNotUsingMic` 和 `unavailable` 改写胶囊本身；前两者同时在问题槽显示原因芯片（“会议在用实体麦”“会议未用 TalkTalk Mic”）。胶囊：原声为绿底；翻译收音、处理与播放为“译音”蓝底；按下未松开为“松开确认”蓝描边；恢复中为“原声已关”；本机就绪或未发送为虚线描边。原声风险为红底，常显，不可收起；音频不可用为 warn 底。电话的绿色“原声”要求真实原声门开启且 `phoneInputIsConfirmed`；否则显示“未接入 Phone”或“本机试说”（虚线）。Feed 在播但读者未确认时显示“仅本机”，并加芯片“Phone 未接收”。读者断开、清理屏障期间显示“正在重新连接 Phone…”（`MeetingAudio.phoneReconnecting`）。视频只显示只读 `ear` 图标，tooltip 与 VoiceOver 为“收听中”。芯片文字不超过 10 个单位、通知不超过 8 个（汉字、拉丁词或插值各计 1），由 `scripts/check-strings.sh` 对 `titlebarLabel`／`noticeLabel` 检查。完整句子进入详情，`show()` 不再按长度分流。问题芯片常显到事实消失，150 ms 淡入；通知为白 28% 描边，4 秒后 300 ms 淡出。`meetingSilent` 显示灰色“未听到对方”。云端隐私说明常驻 16pt `network` 图标加 6pt 蓝点，会话开始时以 transient 浮层自动弹出一次，不抢焦点；问题芯片占位时锚定胶囊。详情浮层宽 320，使用 NSPopover 原生 darkAqua 材质，排除屏幕共享；打开设置窗口的按钮带“…”与 `gearshape`。顶部是 24pt 胶囊加一句后果；电话写“你的原声正在送入 Phone”或“译音正在送入 Phone”，不声称对方已听到。其后是“右⌥ → 动作”、问题完整说明、活动事实、云端说明与操作和设置入口。浮层有关闭按钮，点击外部关闭；输入电平不重建详情或正文；关闭详情不会清除持续问题。胶囊的 VoiceOver 标签为一行（如“发声：原声，对方可听到”），完整说明在 help；发声模式类别切换时以 high 优先级播报一次短句。新的首个问题或通知芯片以完整句子播报一次（risk high、warn medium、通知 low），与胶囊同时变化的风险芯片和“Phone 未接收”不重复。电话设置页与菜单也复用 `VoiceState`。

会议和电话仅在状态带中间的 24pt 曲线带显示一根完整起伏的平滑曲线：峰值振幅 10，颜色为发声状态色 55%。原声和翻译收音为实线，按下未松开为描边态，译音处理或播放时为 1pt 虚线，恢复中、未发送、风险和不可用时没有曲线或收平。真实 RMS 沿用原映射控制振幅，低于 −50 dB 收平，采集关闭或超过 250 ms 无有效输入时移除。曲线不等待 ASR，不表示识别完成或远端送达；窄窗状态带用迷你曲线。曲线不随文字滚动，不自行动画；系统减少动态效果时以静止线条的透明度反馈；窗口隐藏或不在屏幕上时停止绘制。视频字幕不显示波形、不启用麦克风。播放活动以实际 Feed 开始消费至段落结束为依据，与收音并行，不把排队或识别预览当成播放。曲线是透明叠加层，保留现有 NSVisualEffectView glass 材质、按场景保存的背景透明度及系统减少透明度优先逻辑。

三个场景都支持原生黄色按钮最小化，红色关闭只隐藏字幕窗口；两者不切换字幕偏好、不停止采集、翻译、译音或右 Option，仅停止不可见曲线绘制。新字幕、迟到提示和状态变化不得自动恢复窗口；菜单栏“恢复字幕窗口”或 Dock 显式恢复现有阅读视图、尺寸和位置。菜单栏应用在持有原生最小化窗口期间保留 Dock 激活能力，关闭设置不能移除恢复入口；新会话才重置上场的隐藏或最小化意图。远端原文/草稿仍最多每 500 ms 合并显示一次，定稿遵循原有阅读节奏；状态和曲线更新不重建发言正文、不改变手动滚动位置或阅读区分配。

## SPEAK：实体麦到会议输入

```text
实体麦 → MicCapture → MicIngest / VAD / clip cutter
原声：PassthroughGate → PassthroughStage → ringP → Feed → TalkTalk Mic → 会议应用
翻译：ASR → MT → 文本检查 → TTS → ClauseQueue
                                  ├─ ringO → 同一个 Feed
                                  └─ ringO2 → Monitor → 耳机自听
```

会议默认发送实体麦原声。右 Option 改为点按开关：第一次干净点按开始翻译收音，再次干净点按结束，等待采集尾段、识别、翻译、合成及待播译音全部排空后，才自动恢复原声。物理按下仍立即关闭原声，干净松键才确认切换；组合键不触发切换。翻译锁存期间无需持续按键，正常打字和鼠标操作不会结束收音；系统、设备或权限故障会取消锁存，不自动恢复翻译。两次快速点按仅表示正常开始与结束，不再使用旧的双击清空规则。此开关切换发言方式，不是麦克风静音；原声模式仍持续采集。
原声与译音互斥；恢复依据真实 gate、流水线 busy 和播放边界，不能只按 UI 状态或 key-up 判断。会议静音使用会议应用的按钮。
状态展示一次读取按键、待处理动作、流水线和原声门的快照。健康链路在译音排空后、下一次硬件轮询开门前显示普通的“正在恢复原声”，不能误报音频故障，也不能提前声称已发送原声。该判断要求真实采集及 Feed 就绪、硬件轮询未超过现有 lease；设备、安全输入、未知状态等失败仍立即提示。这里只修正展示，不改变原声门的开关、续租或恢复时机。
稳定文本负责切句，完整可修订假设负责预览。当前音频片段上限为 4.5 秒；短尾未提交时显示为 warn“未发送”标记加未发送文字，不能冒充成功翻译。
自己的发言在状态带中实时显示，收回后作为“我的行”进入同一时间线，与远端句对共用有界阅读窗口。排序按本轮首个非空原文的到达时间，60 秒从提交时计；这是内存中的有界阅读窗口，不写日志或磁盘，不作为模型历史。显示裁剪只作用于文本快照，不删除待识别/翻译/播放任务。已结束但没有识别结果的片段不能阻断后续原文或预览。原声模式不显示草稿；迟到的定稿或送达变化会更新已提交的行。
Feed 的第 1 声道送会议 Mic，第 2 声道只送 Test Mic；自检不能借第 2 声道向真实会议发声。

## 实时音频与生命周期约束

- 实时回调在 C 中运行，不分配内存、不持锁、不做文件、网络或日志 I/O；通过有界环和原子状态与 worker 交换数据。
- 采集时间戳来自音频回调，必须与实际写入帧配对；丢帧和溢出不能造成时间错位。跨线程保留原 host time，不能用 worker 到达时间代替。
- 预录 floor 是实际采集时间的硬下限；按键前已发送的原声不能再次作为翻译预录。ring 的容量不等于允许读取的历史范围。
- 原声只能经过 typed gate → PassthroughStage → ringP → Feed；短租约、设备事实、安全输入和按键组合共同守门，过期或未知状态不放行。没有控制 socket 遥控原声入口。
- 外放模式保留远端 VAD 重叠与回声检查；覆盖不足返回未知，不能记为“无远端语音”或“无回声”。
- HAL listener 注册和移除使用独立 control queue，不在其投递回调队列上等待移除。
- 驱动 0.2.3 起，TalkTalk Mic 在构造并首次公布到 HAL 前即保持 `CanBeDefaultDevice=true`，能力值在设备生命周期内稳定；`ttmm` 只表示会话状态，不再修改可选能力。Mic 仍只在 Feed 有客户端或 Mic 有 IO 读者时列入设备清单；应用空闲但保留 Feed 时也可见，结束同传只恢复输入，不等同于退出应用。两者均消失后经过 5 秒宽限移除。正常退出先还原系统输入、释放 Feed，读者也释放后才按宽限移除；仍有读者或异常退出的行为须单独验收。
- App 在设置界面与音频初始化之前启动同一个系统输入 tracker/guard，尽早保留原实体输入；HAL 快照先读取默认设备及其信息，再枚举设备。无会话、无恢复记录但默认输入落到 TalkTalk Mic 时，现有守卫取得管理锁后重新读取快照，写回前再次核对模式、恢复记录和当前默认 UID，避免依据旧观察覆盖新状态。会话仍显式写入 `ttmm=1`，不把始终为真的能力值当作会话已开启；驱动层不计为独立保护。该守卫不能区分用户手选与 macOS 自动选择，也不能提供 HAL 原子比较交换保证；瞬时切换风险及正常退出恢复都需真实验收。默认输出不受此路径修改。
- 系统设置实际可见性、HAL 清单/默认输入和 Phone 实际读帧分别验收。构建 23 / 驱动 0.2.3 已在系统设置 Input 始终打开的条件下通过本机验证：App 空闲时 Mic 自动出现但保留内建默认输入，准备时选中 Mic，结束同传恢复内建输入，正常退出约 5 秒后 Mic 从 HAL 与界面移除，重开 App 自动重现且不抢默认输入，输出保持不变。构建 21/22 的通知方案失败记录保留在[历史验证记录](validation-history.md)。此结果只验证本机设备生命周期，不表示 Phone 或远端已收到声音；真实电话送达按用户要求另行验收。
- `SpeakOutput`、环、Feed、Monitor 和输出 worker 属于应用；`ClauseQueue`、任务账本和翻译上下文属于一次会话。停止时先取消生产者并拆除输出，再复位缓冲。
- 音频服务重启按关门、detach Feed、suspend Monitor、复位本场队列、恢复 Monitor、按需挂回 Feed 的顺序处理；挂起时延后恢复，不重播旧尾巴。
- 会议模式按当前音频设置自动接入默认输入；停止同传或正常退出应用时自动还原，不再弹出“现在/稍后还原”的选择。仍尊重输入管理所有权和用户已经手动切换的设备；无法还原时保留恢复记录并显示具体修复入口。异常退出继续保留守护恢复路径。应用永不更改系统默认输出。
- 引导试说复用正式 Feed，不启用默认原声；必须有确认的可听耳机且没有 Mic 读者或活动会议。读者出现、锁屏、睡眠或路由失效即停止。

## 引擎、翻译与播放

Python/MLX 在独立进程中运行，通过仅本机 HTTP 与每次启动的认证 token 通信；模型、私有 Python 和 venv 位于 bundle 外。一个 GPU worker 按 TTS、SPEAK ASR、LISTEN ASR、后台工作的优先级调度。
默认配置使用 Qwen3-ASR-0.6B 与 Qwen3-TTS-1.7B-Base；较小配置可采用更小 TTS 或 Apple 识别。具体 revision、文件散列、依赖与配置以 `scripts/lib/versions.sh` 和 lock 文件为准。
同场 LISTEN/SPEAK 复用一个 OpenAI 后端及其熔断和连接状态，各方向保留独立开关；语言热切换不能新建后端割裂这些状态。模型设置在下一场生效，术语表按请求读取，最多 30 条生效。
云端只接收待翻译文本、短上下文和术语；未同意或关闭时走 Apple。超时、网络及服务错误按既有预算兜底；翻译结果仍须经过目标文本与数字检查。
有可用声音档案时使用“我的声音”，否则按当前策略使用系统声音或停止发声；界面必须说明实际选择与不可用原因。
同一次发言由第一段合成锁定声音，克隆临时不可用时默认等待或停止发声，不能静默改用系统声音。已有档案读取失败时保持待恢复，不能当成“没有档案”；恢复试听后仍尝试卸载临时声音。实际首声播放记录 clone/system、语言和任务编号等元数据，不记录正文、录音或声音档案标识。所有共享 TTS 解码器的生成任务（含声音预热）在生成器结束或关闭前独占该解码器；达到播放缓冲上限时仍保持所有权，ASR 可继续穿插，不能让预热重置正在合成语音的解码状态。

正式发言与试听的合成请求携带预期 conditioning key。加载时核对请求中的模型、档案 key 与 blob，等待就绪时核对 health 中的 key 摘要；引擎在同一锁内验证当前档案已就绪并捕获其对象/代际，排队任务开始前再次检查。错配、未就绪或被替换时拒绝合成，不能借用当前槽中的其他声音。档案句柄必须来自实际加载的有效 conditioning blob。API v2 的低层离线调用保留可选字段兼容，但正式产品调用必须绑定身份。该校验只证明使用了预期参考，不能证明模型生成的音色与本人一致；`clone` 路由标记与试听相似度均不能充当逐句音色质量证明。

TTS 重复惩罚在 1.0.10 按用户要求恢复原有 1.5 下限。此前 1.0.8 的三组英/德本地 A/B 中用户偏好模型默认 1.05，但之后实际使用和重录效果不理想，故回退该参数；不将任一参数当作音色稳定性保证。保留最近 64 token 惩罚窗口、固定种子、流式预留及现有 runaway/short/echo 保护，不引入整句 F0 筛选后重生成的额外等待。已有参考补尾与 conditioning 不变。

从 1.0.12 起，正常合成、告知语与声音试听统一按声音档案和输出语言固定初始采样种子，不再随每段文字改变。FNV 的 profile/key/mode 前缀保留，英/德各使用冻结的 v1 常量盐，精确保留本轮 C 组听验的数值；盐只是哈希输入，不传给模型、不经过本地化。异常重试仍使用原有 successor seed，且仅在音频尚未释放前重试。1.0.13 增加可选 `sampling_key`：编辑同一声音参考并要保留已听验采样时，用该原身份计算 seed；实际加载、请求校验始终用新 conditioning key。旧档案无该字段时行为不变。保存声音的试听、重建与正式发言一致使用这一采样身份；配套文本从保存的 `script.txt` 读取并核对其哈希。

1.0.13 的句间声音衔接仅在同一录音轮次内启用。克隆请求按生成完成顺序提交，带会话随机 ID/epoch/press/语言组成的临时作用域和显式前驱 job。引擎核对作用域、前驱、声音 key/代际及语言，只把最近一个完整成功、首次生成的前句文本与 codec 作为额外 ICL 条件；真人原参考和 speaker embedding 不变。下一句仍重新建 KV、reset decoder，再用组合参考尾部预热，不把旧生成器跨任务偷接。最多保留一段不超过 8 秒/100 帧、512 字符的前句，不累计合成历史，不写声音档案或磁盘。失败、重试、短段、跑飞、echo、超限不进入缓存；取消、换档案、引擎退出使其失效。新录音轮次和不同语言不会沿用旧句；告知语、试听默认不参与。缺少合格前驱时按真人参考正常生成，不增加等整段发言结束的缓冲。

完成元数据记录 `attempts`、`echo_aborts`、`context_used`，不记录正文、声音 key、seed 或临时作用域标识。句间衔接基于本人的两句英语对照选择，不能以生成成功或该样例外推所有长发言、第一句音色或德语效果。

声音录入使用 `zh-v2` 的 71 字中文稿，引导自然朗读约 10–20 秒；有效时长检查沿用压缩长停顿的计时方式，范围改为 10–20 秒，原始录音上限为 25 秒，读完后 1.2 秒静音自动结束。新稿只用于新录音；既有档案继续使用其保存的文本和 conditioning，不因升级而失效或自动重建。重录过程中试听生成失败不得自动覆盖旧档案，恢复原有声音；成功试听后由用户保存替换。该时长是产品选择，不是官方最佳时长或音色稳定性保证。

翻译轮次隔离：ASR 的上一句原文提示只用于同一轮的非收尾片段，术语表可跨轮；不能把上一轮原文继续作为下一轮识别提示。1.0.14 起，最终/结束尾段只带术语，不带上一句整段原文，降低短尾被上下文诱导成旧句的风险；不按文字相同直接删除，真实重复发言仍须保留。无正文诊断补记相邻采集区间重叠毫秒，以及识别结果字数、是否与同轮上一条接受原文精确相同；这些是定位标记，不代替音频验真。上一轮已结束、仍在 250 ms 收尾时，快速再次开启按新按键边界交接待收尾音频，旧回调不能清除新轮的占用。新轮空字幕快照即使先于音频模式更新到达，也必须清除旧字幕；原声模式的非空识别草稿仍被拒绝。上一轮尚未播完的译音按原规则继续排空，不因新轮开始而重播已消费样本或丢弃未播内容。

`firstSampleEnqueued` 只界定重试边界；已说历史、播放状态和首声指标以 `firstSamplePlayed` 为准。GPU RTF 使用计算时间，不把 HTTP 等待算作 GPU 工作。
告知语在内存中准备，与用户处理并行；失败或超时不能无限阻塞用户句。未验证的码本缩减和自动热备不启用。

## 数据与隐私

- API key 存于 macOS Keychain，不进入命令行、日志、诊断包或引擎；正常音频处理不上传录音或声音档案。
- 常规事件日志默认不含原文和译文。转写、诊断录音和字幕分析分别显式开启，不能以诊断为由默认录制全部会话。
- “本次字幕分析”含原译文和阶段时间，不含音频；不持久化开启偏好，会话结束自动停止。目录 0700、文件 0600，上限 8 MiB / 10,000 行，达到上限在 UI 显示停止。
- 字幕显示时间是 AppKit 提交更新时刻，不是光学显示时刻；缺 voice-end 或参考转写时，不计算伪 EVS、准确率或主观质量分数。
- 诊断导出使用白名单，私有记录按留存策略清理；声音资料与分析文本不进入仓库。合成测试音频同样不提交。

## 构建与验证边界

版本和组件 pins 从 `scripts/lib/versions.sh` 生成；更改后运行 `scripts/gen-pins.sh`，不手改生成文件。安装器验证 revision、大小与 SHA-256，最后写入安装记录。
正式包与开发包使用独立身份；开发 bench 入口只在 `TALKTALK_DEV` 下编译。状态栏使用跨版本稳定 autosaveName，由系统保存布局，不使用未公开排序偏好。
日常开发、验证与交付统一使用正式版；不再生成或运行独立 DEV 应用。内部历史 bench 代码不作为日常交付流程。
常规检查与 fake 测试不应申请权限或改真实设备。真实驱动、麦克风、云端费用和设备恢复检查必须单独安排；CLI passthrough 是退出应用后的离线独占自检，无法取得独占时明确 skip。
自检默认不运行 cloud 或 corun；cloud 需要显式选择，corun 当前明确 skip。构建、签名、mock 回归或一次本地播放不等于完成真人会议、质量或兼容性验收。
